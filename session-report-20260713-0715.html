recommendations

The three biggest prompts each ran 200+ API calls in a single turn ("eb3 Pattern A" 10.0% / "Julia·Helm·Privaty 재인코딩" 8.5% / "julia·cinderella·guillotine" 6.9%). Bundling 3 units + engine capabilities + docs into one turn is efficient on cache, but makes a single mid-turn failure expensive to recover. Committing per-unit (already the practice) keeps the blast radius small — worth keeping.
All 20 cache breaks >100k are main-thread and cluster around /compact (largest reloaded 651k tokens). That's inherent to multi-hour encoding sessions, but each break re-reads the full context uncached. Compacting a little earlier — or splitting a 13-hour session — would trim the most expensive reloads.
engine-test-runner averaged 1.3M tokens/call across just 2 spawns because each cold-starts and re-reads the repo. When you need it repeatedly in one session, continue the existing runner (SendMessage) instead of a fresh spawn to reuse its warm context.
