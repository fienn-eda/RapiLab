# 미하라: 본딩 체인 — 사격장 단발로 잰 체인·지속딜 계수

Fienn 인게임 실측, 2026-08-15. 그녀의 실기록 **0.895x 미달**이 어디서 오는지를
좁히려고 잰 것이고, 답은 **계수가 아니다**로 나왔다.

## RAW (편집 금지)

미하라 **1인** 사격장.

- 표기 ATK **389,164**
- 오버로드 공격력증가 **7.59 + 13.93 + 9.70 + 8.29**
- 철갑 약점 사격장 → 우세코드 영향 없음
- 표적 DEF **100**
- 전투 개시 직후 **271,738** 과 **136,140** 이 여러 번 함께 표기
- 271,738 이 사라진 뒤 **1,361,403** 이 1초 간격으로 표기

## 이 판독이 정한 것

### 1. 표기 ATK에는 오버로드 공격력증가가 안 들어 있다

오버로드 합은 **39.51%**이고, 관측값들이 요구하는 배수가 정확히 그것이다:

```
실제 ATK = 389,164 × 1.3951 = 542,924
```

이 값 하나로 세 관측이 전부 떨어진다(DEF는 계수를 곱하기 전에 뺀다):

| 항 | 계산 | 예측 | 실측 | |
|---|---|---:|---:|---:|
| 체인 어택 | (542,924 − 100) × 50.06% | 271,742 | 271,738 | **1.0000x** |
| 지속딜 1스택 | (542,924 − 100) × 25.08% | 136,145 | 136,140 | **1.0000x** |
| 지속딜 10스택 | (542,924 − 100) × 25.08% × 10 | 1,361,450 | 1,361,403 | **1.0000x** |

### 2. 계수·스택 선형성·DEF 차감이 전부 맞다

- 체인 어택 **50.06%** ✓ (`description_value_05`)
- 지속딜 **25.08%/1초 per stack** ✓ (`description_value_07`)
- **1,361,403 / 136,140 = 10.0000** — 스택 선형성이 소수 4자리로 맞는다
- **271,738 / 136,140 = 1.9960 = 50.06 / 25.08** — 두 계수의 비도 맞는다
- 1인 편성이라 스택이 배틀스타트 방출의 **10에서 멈춘다**(Tighten Up의
  「풀버스트 중 평타 40회당 +1」은 FB가 없으면 안 돈다). 관측과 일치.

## 5인 편성 사격장 (싱크로 682, 같은 날)

### RAW (편집 금지)

- 사격장은 **레벨보정 없음**.
- 편성: 목단 · 에이드: 에이전트 바니 · 네온: 비전 아이 · 아크 레인저 블랙 · 미하라
  (실기록 덱5와 같은 다섯).
- 미하라 스탯은 위 1인 측정과 동일, 스킬 **10/10/10**.
- **두 번째 버스트 사이클부터** 논크리 스킬딜 측정.
- 표기된 스킬딜 두 가지: **580,832** · **11,616,638**.

### 정한 것 1 — 스택 캡은 20이다

```
11,616,638 / 580,832 = 20.0000
```

1스택분과 20스택 합산이 같이 표기된 것이고, 비가 소수 4자리로 20이다.
「실기록을 맞추려면 캡 23.6이 필요하다」(2026-07-31)는 **캡으로는 설명될 수 없다**.

### 정한 것 2 — 버프 곱도 엔진이 맞다

무버프 대비 풀버스트 중 배수를 재면:

```
실측  580,832 / 136,140 = 4.2664x
엔진  189,071 /  44,184 = 4.2792x   (차이 0.3%)
```

엔진 쪽 두 값의 정의를 실측과 맞추는 것이 이 대조의 전부다:

- **분모는 「자기 패시브만」이어야 한다.** 실측의 136,140은 **1인** 편성이라
  아군이 없다. 엔진 시뮬의 t=1 틱을 그대로 쓰면 **에이드: 에이전트 바니의
  `battle_start` 스쿼드 flat ATK**가 이미 들어가 분모가 부풀고, 배수가 3.93으로
  낮게 나온다. 오버로드만 얹은 self-only ATK
  `126,352 × 1.3951 = 176,274`에서 `(176,274 − 100) × 25.08% = 44,184`가 짝이다.
- **분자는 논크리여야 한다.** 엔진 대미지는 크리 **기대값**(`base_crit_rate` 0.15)
  이고 판독은 논크리다. `base_crit_rate=0`으로 돌리면 major가 창 밖 1.0 · 창 안
  1.5가 되어 판독과 같은 축에 선다(그 값이 189,071; 기대값 모델로는 198,525).

**로스터가 싱크로 682가 아니라 레벨 400이라 절대값은 3.08배 다르다.** 그래서
이 대조는 절대값이 아니라 **배수**로만 성립한다 — 실기록도 로스터도 같은 낡은
투자를 쓰므로 캘리브레이션 자체는 일관된다.

## 평타 (같은 5인 편성, 같은 날)

### RAW (편집 금지)

- 풀버스트 **아닐** 때: **33,005** (논코어, 논크리)
- 풀버스트 **구간**: **155,021** (코어히트, 논크리)

### 정한 것 1 — 평타도 엔진이 맞다

지속딜 쌍이 고정한 싱크로 배수 **3.0812**로 엔진 값을 올려 대조하면:

| | 엔진 (레벨 400) | × 3.0812 | 실측 | |
|---|---:|---:|---:|---:|
| FB 밖, 논코어 | 10,692 | 32,944 | 33,005 | **0.998x** |
| FB 중, 코어히트 | 50,462 | 155,484 | 155,021 | **1.003x** |

**주값을 써야 한다.** 버프가 창 안에서 감쇠하므로 한 구간에 값이 여러 개 나온다
(FB 밖 1,556발 중 1,436발이 10,692). `max()`를 뽑으면 가장 드문 순간을 집게 되고,
그러면 FB 밖이 20,185로 읽혀 **엔진이 1.88배 과대**라는 잘못된 결론이 나온다.
플레이어가 화면에서 적는 값은 최빈값이다.

### 정한 것 2 — 사격장에는 적정거리 보너스가 없다

같은 대조를 `effective_range_band="mid"`(MG가 +0.30을 받는 밴드)로 돌리면
FB 밖이 1.298x · FB 중이 1.123x로 **둘 다 크게 어긋난다**. `None`에서만 양쪽이
0.3% 안에 든다. **앞으로 사격장 판독을 엔진과 대조할 때는 밴드를 `None`으로 둘 것** —
실기록 보스(애니힐리오)는 `mid`이므로 그 설정을 그대로 가져오면 안 된다.

## 이 판독이 정하지 못한 것 — 그리고 그게 요점이다

**그녀의 단발 대미지는 이제 전부 검증됐다.** 세 번의 사격장 측정이 모델의 모든
크기 축을 덮었다:

| 축 | 실측 대비 |
|---|---|
| 체인 어택 계수 50.06% | 1.0000x |
| 지속딜 계수 25.08%/스택 | 1.0000x |
| 스택 선형성 · 캡 20 | 10.0000 · 20.0000 |
| 지속딜 버프 곱 | 4.2664 vs 4.2792 (0.3%) |
| 평타, FB 밖 논코어 | 0.998x |
| 평타, FB 중 코어히트 | 1.003x |

**그러므로 실기록의 부족분 100.7M은 크기에 없다.** 남은 후보는 둘이고 둘 다
사격장으로는 못 잰다:

1. **시간 축** — 평타 발수(엔진 8,162)와 지속딜 틱 수(179), 그리고 스택이 캡에
   닿는 시점. 180초 전투의 구조라 단발 판독으로는 접근할 수 없다.
2. **실기록의 유닛별 배분 판독** — 덱5는 **전체로 1.013x**(sim이 과대)인데 그
   안에서 미하라만 0.895x다. 즉 그녀의 미달과 덱메이트의 과대가 서로 상쇄되고
   있고, 이는 게임 로그에서 유닛별 수치를 옮겨 적을 때의 배분 문제와 구분되지
   않는다. `raid_record.py`가 이미 적어 둔 알려진 불일치(25유닛 합계 34.896B vs
   기록된 5덱 총합 34.768B, **0.37% 어긋남**)와 같은 성격이다.

**그녀는 실기록 총딜의 2.8%짜리 유닛이고, 모델은 검증 가능한 모든 축에서 맞았다.
여기서 닫는다.** 다시 열 근거가 될 만한 것은 시간 축을 직접 재는 판독뿐이다 —
예를 들어 180초 동안 그녀가 비운 탄창 수.

## 같이 확인된 것 — 그녀는 이 덱에서 버스트를 못 쓴다

실기록의 `max_bursts: {mihara-bonding-chain: 0}`은 제약이 아니라 **엔진이
어차피 그녀를 안 고른다**는 사실과 일치한다. 캡을 완전히 풀어도 0회다 —
deck5의 Burst 3가 셋(네온 · 아크레인저 · 미하라, 전부 쿨 40초)인데 15개 사이클
슬롯을 **네온 8 + 아크 7**로 둘이 가져간다. 따라서 Bonding Pain(Dragging Chain)은
이 덱에서 영원히 안 나가고, 그녀 딜은 **100% 패시브**(지속딜 58.6% + 평타 41.4%)다.

## 기각된 가설 — 다시 쫓지 말 것

- **「FB 창 밖 지속딜 틱이 갱신 시점 값으로 고정된다」** — 크기는 놀랍도록
  잘 맞았다(그녀만 보면 0.895x → **0.998x**). 그러나 같은 산술을 실기록
  25유닛에 돌리면 아크레인저 1.050 → 1.330, 신데렐라CW 1.237 → 1.285로
  **이미 과대인 유닛을 더 밀어올린다.** 전역 규칙일 수 없다.
- **「체인 방출 타이밍이 틀렸다」** — 원문이 `"at a specific timing"`이라고만
  해서 인코딩이 시각을 가정한 것은 사실이다. 그러나 Restraint Chains 충전이
  「배틀스타트」와 「자기 버스트 후 FB 종료」뿐이고 그녀는 버스트를 안 하므로
  충전이 **1회**, 따라서 **총 10발은 시각을 어떻게 옮겨도 불변**이다.
  최대 이득은 그 10발을 t=0(무버프)에서 FB 안으로 옮기는 2.5M뿐이다.
- **「실제로는 버스트를 썼다」** — 위 「버스트를 못 쓴다」 절.
