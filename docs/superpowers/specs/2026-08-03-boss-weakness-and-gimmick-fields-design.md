# 보스 설정 — 약점 속성 · 속성저지 · 코어 2관통 — 설계

날짜: 2026-08-03

보스 설정 폼에 대한 세 가지 요청(Fienn, 2026-08-03). 서로 독립적이라 따로 착륙시킬 수
있다.

1. 보스 본인 속성 대신 **약점 속성**을 고르게 하고, 드롭다운을 **아이콘 선택**으로 바꾼다.
2. **속성저지 필수** 항목 — 기믹 파훼에 약점속성 니케가 덱당 최소 1기 필요하다.
3. **상시 코어 2관통** 항목 — 코어와 본체가 별개 객체인 보스에서, 관통 특화 니케의
   탄은 코어를 뚫고 뒤의 본체까지 때린다.

## 배경 — 지금의 지형

- 프론트는 `BossProfile.element`(보스 **본인** 속성)를 `<select>`로 받는다.
  `backend/app/elements.py`가 `Water > Fire > Wind > Iron > Electric > Water`
  순환으로 +10%를 준다.
- 덱 합법성 술어는 전부 **유닛만 본다**(`_no_character_clash` ·
  `_tier1_seating_valid` · `_buffer_seat_valid` · `deck_is_valid`). 보스에 의존하는
  제약은 이 코드베이스에 처음 들어온다.
- 관통은 이미 레지스트리 스탯 `has_pierce`로 **시점별로** 추적된다(14개 유닛이
  상시 / 윈도우 / 1발 단위로 보유). "지금 이 유닛에 관통이 있는가"를 물어볼 수 있다.

## A. 약점 속성 아이콘 선택

### A.1 와이어 포맷은 바꾸지 않는다

`BossProfile.element`는 **보스 본인 속성 그대로** 둔다. 약점 ↔ 본인 변환은 UI
경계에서만 일어난다. 이유 둘:

- `squad_engine.boss_is_element` 조건부 스킬이 보스 **본인** 속성을 읽는다(브리드의
  풍압코드 피해량 증가). 와이어를 약점으로 바꾸면 엔진 안에서 되뒤집어야 하고, 변환
  지점이 둘로 늘어난다.
- 저장된 프로필의 `lastInputs.boss.element`가 그대로 유효하다 — 마이그레이션 없음.

### A.2 아이콘 자산

`scripts/download_element_icons.py` — `scripts/download_portraits.py`와 같은 패턴.
받는 곳:

```
https://www.blablalink.com/assets/nikke/version/default/shiftysassets/images/icon-code-{fire,water,wind,iron,electronic}.png
```

내려받을 위치는 `frontend/public/elements/{fire,water,wind,iron,electric}.png`.

- **핫링크하지 않는다.** WebView2 설치형 앱이라 외부 의존은 오프라인에서 깨진다.
  portraits · help 이미지가 이미 `public/`에 받아두는 패턴이다.
- 파일명은 blablalink의 `electronic`이 아니라 엔진 이름 `electric`으로 저장한다.
  ShiftyPad가 전격을 "Electronic"이라 부르는 것은 `shiftypad_normalize.py`가 이미
  기록한 유일한 예외다. 그 예외를 다운로드 스크립트 한 곳에 가둔다.

### A.3 변환 모듈

`frontend/src/lib/elementAdvantage.ts` — 헤더에 `backend/app/elements.py`가 SOURCE
OF TRUTH임을 명시.

```
bossElementFor(weakness: NikkeElement): NikkeElement   // 'Water' -> 'Fire'
weaknessFor(boss: NikkeElement): NikkeElement          // 'Fire'  -> 'Water'
```

서로의 역함수. 왕복 테스트로 고정한다.

### A.4 폼

`BossProfileField`의 속성 `<select>`를 아이콘 라디오 그룹으로 교체.

- 진짜 `<input type="radio" name=...>` 6개(5속성 + "약점 없음")를 시각적으로만
  숨기고 `<label>`이 아이콘을 그린다. 키보드 화살표 이동과 스크린리더가 그대로
  산다 — `<div role="button">`로 만들면 둘 다 잃는다.
- 각 라벨의 접근성 이름은 한글 표기(작열 · 수냉 · 풍압 · 철갑 · 전격)를 쓴다.
  `elementName.ts`가 이미 그 표를 갖고 있다.
- 필드 라벨: 「보스 속성」 → 「보스 약점 속성」.
- draft(`BossProfileDraft.element`)는 A.1대로 보스 본인 속성을 담는다. 변환은
  `checked` 계산과 `onChange` 두 곳에서만.

### A.5 결과 표시

`EvaluationResults`의 덱 카드 라벨 `1번 덱 · 화염` → `1번 덱 · 약점 수냉`. 화면 전체가
약점으로 말하는데 결과만 본인 속성으로 말하면 읽는 사람이 뒤집어야 한다.

## B. 속성저지 필수

### B.1 의미

체크되어 있고 보스가 무속성이 아니면, **덱마다 약점속성 니케가 최소 1기** 있어야
기믹을 파훼할 수 있다.

### B.2 제약이 안 지켜질 때 — 채울 수 있는 덱까지만 (Fienn, 2026-08-03)

약점속성 유닛이 모자라면 **만족시킬 수 있는 덱 수만큼만** 만족시키고, 나머지는
대미지만 최적화한 뒤 ⚠ 배지를 단다. 추천을 아예 거부하지 않는다.

```
로스터 약점속성 3명 / 5덱 요청
  덱 1·2·3 : 약점속성 포함
  덱 4·5   : ⚠ 기믹 파훼 불가 (대미지만 최적화)
```

### B.3 적용 범위 (Fienn, 2026-08-03)

| 모드 | 동작 |
| --- | --- |
| 단일 덱 탐색 | 제약 적용 |
| 5덱 배분 | 제약 적용 (채울 수 있는 덱까지) |
| 드래프트 완성 | 제약 적용 — 빈 자리만 |
| 편성 채점 (evaluate) | ⚠ 경고만 |
| 유니온레이드 탭 | 체크박스 **미노출** |

유니온레이드 탭은 탐색이 없고 유저가 짠 편성을 채점만 하므로 제약이 걸 곳이 없다.
`BossProfileField`에 prop 하나로 감춘다.

### B.4 와이어

`elemental_interrupt_required: bool = False` — `deck_search.BossProfile` dataclass ·
`api.BossProfileIn` · TS `BossProfile` · `BossProfileDraft`.

### B.5 술어

`deck_search.py`에 둘:

```
weakness_element(boss)           # boss.element를 이기는 속성. element가 None이면 None
deck_breaks_gimmick(deck, boss)  # 제약이 꺼졌거나 보스가 무속성이면 항상 True
```

`weakness_element`는 `elements.py`의 순환을 역으로 읽는다 — 표를 프론트처럼 한 벌 더
쓰지 않는다.

### B.6 단일 덱 · 드래프트 완성

덱 **생성 시점**에 거른다. 생성기에 optional `deck_filter`를 넘기고,
`_no_character_clash`와 같은 자리에서 호출한다. 사후 필터가 아닌 이유: 탐색이 제약을
어기는 방향으로 수렴한 뒤에 고치면 손실 폭을 예측할 수 없다.

배선할 생성기 셋:

| 생성기 | 쓰는 곳 |
| --- | --- |
| `shape_combinations` | `search_best_decks` — 단일 덱과 5덱 peel의 실제 진입점 |
| `_shape_completions` | `best_completions` — 드래프트 완성 |
| `feasible_orderings` | `find_best_decks` — API가 안 쓰는 전수 경로 |

`find_best_decks`는 프로덕션 경로가 아니지만 같이 배선한다. 두 경로가 서로 다른 덱을
합법으로 치면 나중에 그 불일치가 버그로 읽힌다 — `deck_is_valid`의 docstring이 같은
이유로 존재한다.

두 가지 fallback이 필요하다.

- **풀 pruning이 약점유닛을 다 잘라낸 경우.** `prune_candidate_pool`은 한계기여도로
  자르므로 약점속성을 보존하지 않는다. 잘린 풀로 만족하는 덱이 하나도 안 나오면
  전수 탐색으로 되돌린다 — `best_completions`에 이미 같은 모양의 fallback이 있다.
- **드래프트가 이미 제약을 어긴 경우.** 유저가 5자리를 약점 없는 유닛으로 다 채웠으면
  빈 자리가 없어 제약을 못 지킨다. 무제약으로 풀고 ⚠ 경고 — B.2의 드래프트판이다.

### B.7 5덱 배분

`allocate_decks`의 greedy peel + 힐클라임 둘 다 손댄다.

**peel 배분.** 덱을 하나 뽑을 때, 남은 약점유닛 수 `w`와 남은 덱 수 `d`에 대해
그 덱은 약점유닛을 **최소 1기, 최대 `max(1, w - d + 1)`기** 갖는다. `w == 0`이면
무제약.

상한이 필요한 이유는 굶주림이다. 상한이 없으면 덱 1이 약점유닛 2기를 가져가 덱 3이
못 받는다 — 만족 덱이 3개에서 2개로 줄어 B.2를 어긴다.

실제 로스터에서 상한은 거의 안 걸린다: 60~80유닛 로스터의 약점속성은 12~16명이라
상한이 8 이상이고, 5인 덱이 거기 닿을 일이 없다. 얇은 로스터(3명 / 5덱)에서만 상한
1로 조여서 덱 1·2·3에 하나씩 흩뿌린다 — B.2가 그린 그림 그대로다.

**힐클라임 가드.** `_try_swaps`의 `admissible`에 불변식 하나를 더한다. 만족 덱 수를
`S`(약점유닛을 1기 이상 가진 덱의 수), `K = min(M, N)`(`M` = 로스터의 약점유닛 수,
`N` = 덱 수)이라 할 때:

> 스왑 후 `S < min(K, 스왑 전 S)` 이면 거부한다.

`min`이 하는 일: peel이 `K`를 채웠으면 `K` 아래로 못 내려가고, 어떤 이유로 `K`에 못
미친 채 시작했으면 **더 줄지만 않으면** 된다. `K` 자체를 하한으로 쓰면 후자에서 모든
스왑이 거부되어 클라임이 통째로 죽는다.

덱별 예약 장부를 두지 않고 **전역 카운트**로 판정한다. 클라임이 약점유닛을 덱 사이로
옮기는 것 자체는 자유롭고, 총 만족 수만 지키면 된다. 5덱을 세는 상수 비용이라 핫루프에
부담이 없다.

### B.8 경고 배지 — API 변경 없음

`GET /api/supported-units`가 슬러그별 `element`를 이미 준다. 프론트가 결과 덱의
슬러그와 제출한 보스 속성만으로 스스로 판정한다. 응답 모델에 필드를 더하지 않는다.

⚠가 붙는 곳: 편성 채점 모드의 각 덱, 그리고 5덱 배분·드래프트에서 못 채운 덱.

## C. 상시 코어 2관통

### C.1 대미지 모델 (Fienn, 2026-08-03)

관통 특화 니케의 통상공격 1발이 **인스턴스 2개**를 낳는다.

```
코어:  base × ... × (1 + 1.0(코어) + 크리 + FB + 사거리)
본체:  base × ... × (1 +            크리 + FB + 사거리)
```

본체 히트는 **코어 보너스만 빠진 풀 대미지**다. 감쇠 계수 없음. 다른 버프·버킷은
둘 다 동일하게 받는다. 코어 보너스 1.0, 나머지 0인 상황이면 `2.0 + 1.0 = 3.0`으로
1.5배.

관통이 아닌 니케는 코어를 때릴 수는 있지만 뒤의 본체는 못 때린다 — 변화 없음.

### C.2 와이어

`pierce_hits_body_behind_core: bool = False`.

**`core_hittable`에 의존한다.** 코어를 못 때리면 2관통이 성립하지 않는다. UI에서 이
항목을 켜면 「코어 피격 가능」도 함께 켜지고, 「코어 피격 가능」을 끄면 이것도 꺼진다.
엔진은 `core_hittable and pierce_hits_body_behind_core`로 읽어, 와이어가 모순 상태로
와도 조용히 틀린 숫자를 내지 않는다.

### C.3 엔진

`raid_simulator.py`의 phase 2 damage_log 생성부(현재 1442행의 리스트 컴프리헨션).
이벤트가 아래를 전부 만족하면 `hits_core=False`인 인스턴스를 **하나 더** 낳는다.

- `source == "normal_attack"`
- `hits_core`가 True (= `core_hittable` && `core_eligible`)
- 그 시점 `has_pierce > 0`

추가 인스턴스의 `source`도 `normal_attack`이라 `_summarize`의 3분할(버스트 / 통상 /
스킬)이 안 깨진다.

### C.4 이 조건이 자동으로 배제하는 것

- **Sustained / Distributed 통상공격.** `NON_CORE_DAMAGE_TYPES`라 애초에
  `hits_core`가 False다. 코어를 못 때리는 탄이 관통해 뒤를 때린다는 근거가 없으므로
  보수적으로 둔다.
- **「코어 명중 대미지」(`core_strike`).** 코어 보너스를 받지만 스킬 대미지이고,
  툴팁상 실제로 때리는 것은 본체다 — 뒤에 때릴 게 없다. `source == "normal_attack"`
  조건이 거른다.
- **관통 유닛의 스킬 대미지.** 같은 조건이 거른다. 관통은 통상공격의 성질이라는
  기존 판정(`test_pierce_needs_the_property.py`)과 일관된다.

### C.5 무기변형 세그먼트도 포함된다 (Fienn, 2026-08-03)

무기변형 세그먼트의 발사는 별도 경로가 아니라 **같은 사격 루프**를 타고
`source="normal_attack"`으로 기록된다(`raid_simulator.py:1115`). 따라서 변형샷도
C.3의 조건을 그대로 만족하며, **관통을 들고 있으면 2관통이 붙는다.** 예외를 두지
않는다.

| 유닛 | `has_pierce` 창 | 2관통이 붙는 발 |
| --- | --- | --- |
| 맥스웰 | `own_burst_activate` 1발짜리 | 변형이 정확히 1차지샷(`until_shots: 1`)이라 그 한 발 |
| 스노우화이트 | 동일 | 동일 |
| 레드후드 | `battle_start`부터 영구 (Wild Tooth "Gain Pierce continuously") | 변형 33발 + 기본무기 통상공격 **전부** |

레드후드의 결이 다르다는 점이 중요하다. 그의 관통은 변형에 붙은 것이 아니라 상시라서
이 보스에서 **통상딜 전체가 1.5배**가 된다. 상시 관통을 가진 다른 유닛들(밀크: 블루밍
버니 · 도로시 · 프리카 · 신데렐라: 크리스탈 웨이브 등 `battle_start` 계열)도 마찬가지다.

## 테스트

### A

- `elementAdvantage.ts` 왕복: 5속성 모두 `weaknessFor(bossElementFor(x)) === x`.
- `BossProfileField`: 아이콘을 고르면 `onChange`가 **보스 본인 속성**을 담아 부른다
  (수냉 아이콘 클릭 → `element: 'Fire'`).
- 저장된 프로필 복원: `element: 'Fire'`인 draft가 수냉 아이콘을 선택 상태로 그린다.
- 「약점 없음」이 `element: null`로 왕복한다.

### B

- `deck_breaks_gimmick`: 제약 off / 무속성 보스 / 약점유닛 있음 / 없음 4갈래.
- 단일 덱: 제약을 켜면 반환된 덱이 반드시 약점유닛을 갖는다. 로스터에 약점유닛이
  아예 없으면 무제약과 같은 답을 낸다(거부하지 않는다).
- 드래프트: 빈 자리가 있으면 제약을 지키고, 5자리가 다 찼고 약점유닛이 없으면
  무제약으로 푼다.
- 5덱 배분 — **B.2를 직접 고정한다.** 약점유닛 3명 / 5덱 로스터에서 만족 덱이 정확히
  3개. 약점유닛 0명이면 0개이고 예외가 안 난다. 약점유닛이 넉넉하면 5개 전부.
- 힐클라임 가드 두 갈래: `K`를 채운 상태에서 만족 수를 떨어뜨리는 스왑이 거부되고,

## 이 설계가 가르지 못하는 것

- **2관통 보스에서의 실측 대조가 없다.** C를 켜면 관통 유닛의 통상딜이 1.5배가 되어
  추천이 관통 쪽으로 크게 기운다. 기존 캘리브레이션은 이 플래그가 꺼진 보스로 잰
  것이라 불변이지만, **켠 상태의 결과를 실기록과 맞춰본 적은 없다.** 해당 보스에서
  한 번 재는 것이 다음 순서다.
- **본체 히트가 사거리 항을 코어와 같이 받는지.** C.1은 "코어 보너스만 뺀 풀 대미지"
  이므로 같이 받는 것으로 잡았다. 같은 탄의 같은 순간이므로 다를 이유가 없지만
  측정된 것은 아니다.
- **변형 무기의 탄이 실제로 코어를 뚫는지.** C.5는 "관통이면 2관통"을 균일하게
  적용한다(Fienn의 결정, 2026-08-03). 레드후드의 레드 울프 캐논 · 맥스웰의 관통샷 ·
  스노우화이트의 일곱 난쟁이가 인게임에서 기본 무기와 같이 구는지는 확인된 바 없다.
  특히 스노우화이트처럼 **원래 관통이 없다가 변형 순간에만 얻는** 경우가 갈릴 여지가
  크다.
- **2관통이 3관통 이상인 보스가 있는지.** 항목 이름이 "2관통"이므로 2로 고정한다.
- **속성저지가 덱당 1기로 충분한지.** 기믹이 요구하는 최소 인원이 보스별로 다를
  가능성은 다루지 않는다. 필요해지면 bool을 정수로 넓히면 된다.
