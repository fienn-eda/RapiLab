# 소장품 차지대미지 배율을 무기변형 세그먼트에 전달 — 설계

날짜: 2026-08-03

## 문제

RL·SR 소장품의 「차지 대미지 배율」은 `collectible_effects`의 `"weapon"` 배치를
타고 `user_roster`에서 `weapon_stats["charge_damage_percent"]`에 곱해진다. 무기변형
세그먼트의 프로파일은 skill_rules 빌더가 **스킬 슬롯에서 직접** 만들기 때문에 그
곱셈을 거치지 않는다. 변형 중 그 유닛의 차지 데미지가 소장품 몫만큼 낮게 계산된다.

`docs/engine-gaps.md`가 이 갭을 **8기**로 기록하고 있는데 틀렸다. 등록된 무기변형
빌더 16개를 프로파일의 출처로 분류하면 **2기**다.

| 분류 | 유닛 |
| --- | --- |
| **걸림** | **maxwell**(소장품 lv5 → 1.0631) · **red-hood**(lv15 → 1.0947) |
| `weapon_stats`를 읽음 | snow-white-heavy-arms |
| 침묵 세그먼트(`damage_percent: 0.0`) | milk-blooming-bunny · scarlet-black-shadow |
| 프로파일에 차지댐 없음 | laplace · laplace-signature · takina-inoue · moran(-signature) · laplace-ultimate-hero |
| 소장품이 `"effect"` 배치 | snow-white(AR) · zwei(-signature)(SG) · nayuta(SMG) |
| 변형 빌더 없음 | anis-star · modernia |

둘 다 캘리브레이션 기록 덱에 없다.

## 측정 — 이 설계가 기대는 사실

Fienn, 2026-08-03. 편성 로자나 / 센티 / 맥스웰, 작열 속성 사격장(수냉 약점),
**MID** 위치, 맥스웰 스킬레벨 1/1/1, 소장품 SR 5단계(차지대미지 6.31% → 1.0631).

원본(논크리):

```
사이클 A   변형샷 코어 7014461   기본풀차지 코어 2786144   기본풀차지 논코어 1671686
사이클 B   변형샷 논코어 4208677  기본풀차지 코어 2786144   기본풀차지 논코어 1671686
```

두 사이클의 기본무기 값이 동일하므로 덱 상태는 같았다.

major 버킷을 각 사격 유형에서 직접 뽑는다(맥스웰의 소장품은 차지대미지라 코어
소스가 0이므로 `코어/논코어 = (M+1)/M`):

```
기본무기  1.6666671  ->  M = 1.4999991
변형샷    1.6666665  ->  M = 1.5000004
```

둘 다 **1.5** — 풀버스트만, 코어 소스 없음, 사거리 항 없음. M이 같으므로 보정은 1이다.

```
논코어 비율 (변형 ÷ 기본풀차지)                          2.5176220
  배율이 세그먼트에도 붙는다  (144.85×3.00) ÷ (69.04×2.50)  2.5176700   잔차 +4.9e-05
  안 붙는다                  위 ÷ 1.0631                   2.3682400   잔차 -1.5e-01
```

**판정: 붙는다.**

### 이 판독의 캐비엇

비율은 **분자·분모에 공통인 인자에 눈이 먼다.** 위 결과가 엄밀히 말하는 것은
`k_변형 = k_기본`이지 `k = 1.0631`이 아니다. 기본 무기 쪽이 1.0631이라는 것은
에이드: 에이전트 바니의 사격장 판독 7개(절대값 적합, `250% × 1.0631 = 265.775%`,
0.002% 이내)가 확정했고, 이 측정은 그 위에 얹혀야 체인이 닫힌다.

### 함께 나온 것

MID에서 변형 캐논의 사거리 항이 0이다. SR의 유효사거리 밴드는 `far`이므로 기본
무기가 0인 것은 예상대로이고, **변형 캐논도 0**이라는 것은 그것이 `mid` 밴드(AR·MG)로
취급되지 않는다는 뜻이다. `far`인지 `near`인지는 이 측정이 가르지 못한다.

## 설계

### 1. 배율을 값 딕셔너리에 실어 보낸다

`roster.assemble_simulation_inputs`는 이미 유닛마다
`"caster_weapon_stats": spec.weapon_stats`를 값에 넣고 있고, `_passive_effects`는
`collectible_modifiers`를 호출하면서 무기 배율을 버리고 있다(`_, collectible = ...`).
필요한 값이 이미 그 자리에 있다.

값에 키를 하나 더한다.

```
"caster_charge_damage_multiplier": <collectible_modifiers(...)[0]의
                                    "charge_damage_percent", 없으면 1.0>
```

전체 딕셔너리가 아니라 스칼라 하나를 넘긴다 — 오늘 필요한 것이 그것뿐이고, 이름이
곧 내용이다.

### 2. 스킬 유래 프로파일을 가진 빌더가 곱한다

**maxwell** — 변형 무기의 풀차지 배수 전체가 스킬 값이다.

```
"charge_damage_percent": float(pierce["description_value_03"]) * multiplier
```

**red-hood** — 두 항의 합이다. 배율은 **변형 무기 자신의 풀차지 배수에만** 붙인다.

```
"charge_damage_percent": full_charge_percent * multiplier + converted * 100
```

`converted * 100`은 Glaring의 차지속도→차지대미지 변환이므로 무기의 기본 스탯이
아니다. 이 분해는 `snow_white_heavy_arms`가 이미 하고 있는 것과 같은 모양이다
(`weapon["charge_damage_percent"](배율 포함) + shades 가산항`).

**다른 빌더는 건드리지 않는다.** 위 분류표의 나머지는 곱할 대상이 없거나 이미
`weapon_stats` 경유로 받고 있다.

### 3. 무반응 방어 테스트

손으로 유지하는 유닛 목록은 조용히 낡는다(`docs/insights.md`의 힐 제공자 목록
전례). 대신 **행동 불변식**을 검사한다. 등록된 무기변형 빌더 각각에 대해:

> 프로파일에 `charge_damage_percent`가 있고 0이 아니라면, `caster_weapon_stats`의
> 차지댐을 바꾸거나 `caster_charge_damage_multiplier`를 바꿨을 때 **둘 중 하나에는
> 반응해야 한다.** 둘 다에 무반응이면 실패.

헤비암즈는 무기 쪽에 반응하고, 맥스웰·레드후드는 배율에 반응한다. 차지댐이 없는
프로파일은 면제다. 새 변형 유닛이 스킬 값을 하드코딩하면서 배율을 소비하지 않으면
이 테스트가 잡는다.

### 4. 회귀 기대값

| 대상 | 기대 |
| --- | --- |
| maxwell 변형샷 | 차지 데미지 **×1.0631** (그의 소장품 5단계) |
| red-hood 변형샷 | `full_charge_percent` 항이 **×1.0947** |
| 그 외 전 유닛 | 변화 0 |
| 5덱 합계 · 캘리브레이션 | 변화 0 — 두 유닛 다 기록 덱에 없다 |

캘리브레이션이 안 움직이는 것이 이 작업의 성공 신호다.

## 이 설계가 가르지 못하는 것

- **가산 스킬 항에도 배율이 붙는지.** red-hood의 `converted * 100`과
  snow-white-heavy-arms의 `shades` 항이 여기 해당한다. 맥스웰의 변형에는 가산 항이
  없어 이 측정이 가르지 못했다. 「기본 스탯만 스케일」이라는 툴팁 해석을 따라
  붙이지 않으며, **heavy-arms의 기존 코드는 건드리지 않는다.**
- **변형 캐논의 유효사거리 밴드.** MID에서 항이 0이라는 것만 확인됐다.
- **소장품 사다리의 다른 칸.** 맥스웰은 5단계, 즉 에이드와 같은 칸이다.
- **RL 유닛에서의 동일성.** 측정 대상은 SR 하나였다.
