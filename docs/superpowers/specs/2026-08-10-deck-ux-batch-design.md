# 덱 편성 조작과 표기를 고친다 — 프론트 9건

날짜: 2026-08-10

Fienn의 개선 메모에서 나온 **프론트엔드 9건**을 다룬다. 메모의 아홉 번째인
「유니온 레이드 기대딜량에 레벨 400 보정 대신 실제 스탯」은 스탯 모델과 그
검증에 걸리는 일이라 이 스펙에 넣지 않는다 — 이유는 §10에 적는다. 여기 아홉
번째는 그 자리에 들어온 **보스 설정 접기**(§8)다.

아홉 건은 성격이 넷으로 갈린다.

- **조작이 안 되는 것**(§1–§3) — 눌러야 할 곳이 안 눌리고, 옮길 방법이 없고,
  빼놓은 유닛이 다시 들어온다.
- **표기가 틀린 것**(§4–§6) — 같은 값을 쓰는 두 뱃지 중 하나만 횟수를 달고,
  덱과 저장 이름이 그 덱이 무엇인지 말하지 않는다.
- **동작이 거짓말하는 것**(§7) — 첫 저장인데 보관 상한 경고가 뜬다.
- **화면이 너무 긴 것**(§8) — 보스 설정 폼이 유니온에서 세 벌 서서 편성 칸을
  아래로 민다.

## 1. 유닛 카드는 테두리 안 어디를 눌러도 반응한다

### 지금

두 화면이 서로 다르게 눌린다.

| 화면 | 컴포넌트 | 버튼이 감싸는 것 | 버튼 밖에 남는 것 |
|---|---|---|---|
| 니케 풀 | `NikkeCard` | 초상화 `<img>`만 | 이름, 스킬레벨, 오버로드, 돌파/코어 배지 |
| 솔로·유니온 팔레트 | `UnitPalette` | 초상화, 이름, B티어·속성, 오버로드 | 돌파·코어·S1·S2·B 다섯 줄(`palette__stats`) |

그래서 니케 풀에서 오버로드 줄을 눌러도 제외/포함이 안 되고, 팔레트에서
스킬레벨 칸을 눌러도 배치가 안 된다.

### 바꿀 것

**세 탭 모두 카드 테두리 안 전체가 하나의 표적이 된다.** 니케 풀은 제외/포함,
팔레트는 배치다.

### 어떻게

카드를 통째로 `<button>`으로 감싸는 방법은 **쓸 수 없다.** `<button>`의 콘텐츠
모델은 phrasing content뿐인데 두 카드 모두 `<h3>`와 `<ul>`을 품고 있다.

CSS로 버튼의 `::after`를 카드 전체에 늘리는 방법도 **쓰지 않는다.** 동작은
하겠지만 **잴 수가 없다** — jsdom은 레이아웃을 계산하지 않고 이 저장소의
Vitest는 `css: false`로 돈다. 오버로드 줄에 발생시킨 클릭이 덮개에 맞는지를
테스트가 볼 방법이 없으므로, 구현이 맞아도 테스트는 빨갛고 구현이 틀려도
테스트는 그걸 모른다.

대신 **클릭 핸들러를 카드 껍데기로 올리고, 버튼은 자기 핸들러를 갖지 않는다.**

```tsx
<section className="card roster-card" onClick={handleCardClick}>
  <button type="button" className="roster-card__use" aria-pressed={!excluded} aria-label={`${title} 사용`}>
    …초상화…
  </button>
  <h3>…</h3> <SkillLevels/> <OverloadLines/>
</section>
```

한 번만 불리는 이유: 핸들러가 껍데기에 하나뿐이다. 초상화를 눌러도 버튼에서
껍데기로 **버블링**해 같은 핸들러에 한 번 닿는다. 키보드도 그대로다 — 버튼에
포커스를 두고 `Enter`/`Space`를 누르면 click 이벤트가 나고, 그것도 버블링한다.

이 방식을 고른 이유:

- **jsdom에서 잴 수 있다.** 오버로드 `<span>`에 클릭을 발생시키면 껍데기까지
  버블링하므로, 레이아웃 없이도 실제 동작을 재현한다.
- `aria-pressed`·`aria-label`을 단 버튼이 그대로 남아 접근성과 기존 테스트가
  유지된다.
- `UnitPalette`의 `draggable`/`onDragStart`는 버튼에 그대로 둔다 — 드래그는
  click이 아니라 영향이 없다.

**반드시 같이 넣어야 하는 가드:** 껍데기 핸들러는 버튼의 `disabled`를 우회한다.
비활성 버튼은 클릭을 안 내지만, 껍데기의 다른 영역을 누르면 핸들러가 그대로
불린다. 그래서 핸들러 자신이 같은 조건을 다시 확인해야 한다:

```tsx
const handleCardClick = () => {
  if (isUsed || isExcluded) return
  onSeat(unit.slug)
}
```

이 가드가 §3(제외한 유닛은 배치되지 않는다)의 실제 시행 지점이다. 빠지면
팔레트에서 제외된 칩의 스킬레벨 칸을 눌러 배치할 수 있게 된다.

**가드는 팔레트의 배치 모드에만 건다.** 니케 풀 탭에서 껍데기 핸들러가 부르는
것은 `onToggleExclude()`이고, 거기서는 제외된 유닛도 계속 눌려야 한다 — 그것이
제외를 되돌리는 유일한 방법이다. 즉 세 탭의 껍데기 핸들러는 같은 배선을 쓰되
가드 조건이 다르다:

| 탭 | 껍데기 클릭이 부르는 것 | 가드 |
|---|---|---|
| 니케 풀 (`NikkeCard`) | `onToggleExclude()` | 없음 |
| 솔로·유니온 (`UnitPalette`) | `onSeat(slug)` | `isUsed \|\| isExcluded`면 무시 |

## 2. 배치된 유닛을 다른 덱으로 옮긴다 — 집기 → 놓기

### 왜 드래그가 아닌가

좌석에는 이미 HTML5 드래그가 붙어 있다(`DraftEditor`의 `draggable` +
`onDragStart`). 그런데 **WebView2는 `dragstart`만 내고 그 뒤 이벤트를 안 낸다** —
설치형 앱에서 드래그는 죽어 있고, 이건 우리 코드가 아니라 호스트 문제다. 같은
번들이 Chromium에서는 정상 동작한다. 그래서 앱에서 실제로 쓸 수 있는 이동
수단은 포인터/클릭뿐이다.

기존 드래그 경로는 **지우지 않는다.** 브라우저에서는 여전히 동작하고, 지울
이유가 없다.

### 상태

`DraftEditor`에 로컬 상태 하나를 더한다.

```ts
const [heldSeat, setHeldSeat] = useState<{ deckIndex: number; seatIndex: number } | null>(null)
```

들린 좌석은 시각적으로 구분된다(`draft-editor__slot--held`).

### 전이표

`heldSeat === null`일 때:

| 누른 곳 | 결과 |
|---|---|
| 채워진 좌석(고정 아님) | 그 좌석을 든다 |
| 채워진 좌석(고정) | 아무 일 없음 — 고정은 뺄 수 없다 |
| 빈자리 | 아무 일 없음 |
| 팔레트 유닛 | 기존 동작 — 활성 덱의 첫 빈자리에 배치 |

`heldSeat === X`일 때:

| 누른 곳 | 결과 | 이후 |
|---|---|---|
| 같은 좌석 X | **제거** | 놓음 |
| 다른 좌석 Y — 비어 있음 | X의 유닛을 Y로 **이동** | 놓음 |
| 다른 좌석 Y — 차 있음(고정 아님) | X와 Y를 **교환** | 놓음 |
| 다른 좌석 Y — 고정 | 아무 일 없음 | **계속 듦** |
| 팔레트 유닛 P | X 자리를 P로 **교체**, X의 유닛은 풀로 | 놓음 |
| `Esc` | **집기 취소** | 놓음 |

같은 덱 안의 다른 자리로 옮기는 것도 같은 규칙을 탄다. 따로 막을 이유가 없고,
막으면 규칙이 하나 늘어난다.

「차 있는 자리 = 교환」은 기존 드래그 드롭(`handleSeatDrop`)이 이미 교환이라
**두 경로가 같은 규칙**이 되게 하는 선택이다.

### `Esc`가 필요한 이유

Fienn이 고른 조합에서 「같은 좌석 재클릭」은 제거다. 그래서 집었다가 마음이
바뀌었을 때 되돌릴 제스처가 없으면, 취소하려고 누른 클릭이 유닛을 지운다.
`Esc`는 그 함정만 막는 최소한의 출구다.

### 빈자리를 진짜 버튼으로

지금 빈자리는 `aria-hidden="true"`인 장식용 `<li>`다(`+` 글리프만 그린다).
놓기를 받으려면 눌리는 것이 되어야 하므로 **무언가를 들고 있을 때만**
`<button>`으로 그리고 `aria-hidden`을 뗀다. 아무것도 안 들었을 때는 지금
그대로 장식으로 남는다 — 누를 수 없는 것을 버튼으로 보이게 하지 않기 위해서다.

## 3. 제외한 유닛은 배치되지 않는다

### 지금

`UnitPalette`에서 제외된 유닛은 `palette__item--excluded`로 흐려지기만 하고
`disabled`에는 안 들어간다:

```tsx
disabled={onSeat !== undefined && isUsed}
```

그래서 니케 풀에서 「안 쓴다」고 정해도 솔로·유니온 탭에서 눌리면 덱에 들어간다.

### 바꿀 것

```tsx
disabled={onSeat !== undefined && (isUsed || isExcluded)}
```

배치 화면에서만 막는다. **니케 풀 탭에서는 `onSeat`이 없으므로 제외된 유닛도
계속 눌린다** — 거기서의 클릭은 배치가 아니라 제외 해제이고, 그것까지 막으면
한 번 제외한 유닛을 되돌릴 수 없게 된다.

`disabled`만으로는 부족하다. §1에서 클릭 표적이 카드 전체로 넓어지므로
**버튼 밖 영역은 `disabled`를 우회한다.** 실제 차단은 §1의 껍데기 핸들러 가드가
하고, 여기 `disabled`는 그 칩이 눌리지 않는다는 것을 보이고 읽히게 하는 역할이다.
둘 다 필요하다.

### 이미 앉아 있던 유닛

`UnionRaidPanel`에는 새로 제외된 유닛을 좌석에서 빼는 효과가 이미 있다
(`excludedKey`를 보는 effect). `RecommendPanel`에 같은 것이 있는지 확인하고,
없으면 같은 규칙으로 맞춘다. 두 탭이 다르게 동작할 이유가 없다.

## 4. 미란다 — 공격력에도 횟수를 붙인다

`MirandaTargets`에서 파워업!은 **공격력과 크댐을 함께** 준다. 두 뱃지가 같은
`powerCount`에서 나오는데 횟수가 크댐에만 붙어 있다:

```tsx
<span className="miranda-badge miranda-badge--silver"><span>공격력</span></span>
<span className="miranda-badge miranda-badge--silver">
  <span>크댐</span>
  {powerCount < total && <b>{powerCount}/{total}</b>}
</span>
```

공격력 뱃지에 같은 조건의 `n/T`를 붙인다. 새 계산은 없다 — 값은 이미 있다.

## 5. 유니온 저장 이름 = 각 덱의 약점

### 지금

```ts
const suggestUnionRunName = (at: Date, numBattles: number): string =>
  `유니온 ${numBattles}전투 · MM-DD`
```

「유니온 3전투」는 그 저장물이 **무슨 보스**를 잰 것인지 말하지 않는다.

### 바꿀 것

각 덱 보스의 약점 속성을 순서대로 나열한다. 예: `수냉 작열 풍압`.

- 속성은 `weaknessFor(boss.element)` → `elementLabel`로 뽑는다. 보스의
  `element`는 **보스 자신의 속성**이고 약점은 그 상성이다 — `BossSummary`가
  이미 쓰는 변환이다.
- 속성을 안 고른 덱은 `약점없음`으로 **자리를 지킨다.** 건너뛰면 몇 번째 덱이
  비었는지가 이름에서 사라진다.
- **날짜는 넣지 않는다.** `SavedRunList`가 이름 옆에 `MM-DD HH:MM`을 항상
  따로 찍는다.

### 같은 이름으로 여러 번 저장해도 되는가

된다. 확인한 결과:

- `id`는 `makeRunId(savedAt, existing)` = `저장시각-연번`이라 같은 밀리초에
  저장해도 충돌하지 않는다.
- `renameRun`·`deleteRun`은 전부 `id`로 찾는다. 이름은 어디에서도 키가 아니다.
- 목록은 이름 옆에 저장 시각을 찍으므로 같은 날 같은 약점으로 다섯 번 저장해도
  화면에서 구분된다.

즉 같은 날 같은 속성 조합을 여러 번 재는 Fienn의 사용 방식은 **이미 안전하고,
이 변경이 그것을 깨지 않는다.** 별도 조치가 필요 없다.

## 6. 덱 라벨 = 보스 이름 + 약점 아이콘

### 지금

유니온 탭의 덱은 `덱 1`·`덱 2`·`덱 3`으로 불린다. 어느 덱이 어느 보스인지는
위쪽 보스 설정 칸을 따로 봐야 안다.

### 바꿀 것

라벨을 **보스 이름 + 약점 속성 아이콘**으로 바꾼다. 폴백은 셋:

1. 회차에서 보스를 골랐으면 → `[아이콘] 인디비리아`
2. 보스 없이 약점만 골랐으면 → `[아이콘] 수냉`
3. 둘 다 없으면 → `덱 1` (지금 그대로)

아이콘은 `lib/elementIcon.ts`의 `WEAKNESS_ICON`을 쓴다 — `BossProfileField`와
`RaidRotationPicker`가 이미 쓰는 것이라 새 에셋이 없다.

### 보스 이름을 끌어올린다

지금 보스 이름은 `BossProfileField`의 **로컬 상태**(`pickedName`)에만 있고
부모로 올라오지 않는다. `onChange`가 내는 `BossProfileDraft`에는 이름 칸이
없다. 라벨을 그리려면 `UnionRaidPanel`이 이름을 알아야 하므로
`BossProfileDraft`에 이름을 더한다.

지켜야 할 것 둘:

- **속성이 바뀌면 이름을 버리는 기존 가드를 유지한다.** 지금
  `BossProfileField`는 고른 보스의 속성이 현재 값과 안 맞으면 이름을 안 쓴다.
  이 가드가 없으면 유저가 속성만 바꿨을 때 라벨이 옛 보스 이름을 계속
  말하게 된다 — **라벨이 거짓말하는 상태**다.
- **백엔드로 새지 않게 한다.** 이름은 표시용이고 시뮬레이션 입력이 아니다.
  `BossProfile` wire 타입에 넣지 않고, draft→request 변환에서 떨어뜨린다.
  타입을 옵셔널로 두어 얼버무리지 않는다 — 옵셔널 wire 필드는 이 저장소에서
  이미 한 번 타입 구멍을 만든 적이 있다.

## 7. 첫 저장인데 보관 상한 경고가 뜬다

### 증상

유니온 결과를 **처음** 저장해도 `보관은 50개까지예요…`가 뜬다.

### 무엇이 의심스러운가

`useProfiles`의 `keepRun`이 `setState` 업데이터 **안에서** 정한 값을 그 **밖에서**
동기적으로 읽는다:

```ts
let accepted = false
setState((current) => {
  const next = pureSaveRun(current, args.key, args.run)
  accepted = next !== current
  return next
})
return accepted          // 업데이터가 아직 안 돌았으면 false
```

React는 업데이터를 항상 즉시 실행하지 않는다. 안 돌면 `accepted`는 `false`로
남고, `SaveRunButton`은 그것을 「상한에 걸림」으로 읽는다.

순수 함수 `saveRun` 자체는 멀쩡하다 — 상한 판정도, 참조 동일성으로 거절을
알리는 규약도 맞다. 깨진 것은 그 규약을 React 밖으로 옮기는 배선이다.

### 단정하지 않는다

같은 증상을 내는 경로가 하나 더 있다. `App`이 `state.activeKey`가 비면
`saveRun`을 부르지도 않고 `false`를 돌려준다. 이쪽이면 고칠 자리가 다르다.

그래서 **재현하는 실패 테스트를 먼저 쓰고**, 그것이 어느 경로를 빨갛게 하는지
확인한 뒤에 고친다. 지금 초록인 `useProfiles.test.ts`가 이 버그를 놓치고 있다는
사실 자체가, 무엇을 재야 하는지 아직 모른다는 뜻이다.

## 8. 보스 설정을 접는다

### 지금

`BossProfileField`는 항상 펼쳐진 `<fieldset className="group">`이다. 유니온에서
3전투를 고르면 속성 라디오·코어·방어력·전투시간이 든 긴 폼이 **세 벌** 서고,
정작 손을 대는 편성 칸이 화면 아래로 밀린다.

### 바꿀 것

legend의 버튼을 누르면 본문이 접히고 **머리에 보스 이름만 남는다.**

- **솔로·유니온 두 탭 모두.** 같은 컴포넌트라 한 곳만 고치면 된다.
- **기본은 항상 펼침.** 회차 보스를 골라도 자동으로 접지 않는다 — 접는 것은
  유저가 누를 때뿐이다.
- 접힘 상태는 컴포넌트 로컬 상태다. 저장하지 않는다.

### 머리에 무엇을 쓰나

§6의 덱 라벨과 **같은 폴백을 같은 함수로** 쓴다:

1. 회차 보스를 골랐으면 → `[아이콘] 인디비리아`
2. 약점만 골랐으면 → `[아이콘] 수냉`
3. 둘 다 없으면 → `보스 설정`

솔로도 `rotation`을 받으므로(`latestRotationFor(rotations, 'solo')`) 두 탭에서
같은 세 단계가 그대로 성립한다.

**머리는 펼쳤을 때도 같은 이름을 쓴다.** 접혔을 때만 이름으로 바뀌면 규칙이
둘이 되고, 펼친 폼의 제목이 `보스 설정`이면 그 폼이 어느 보스 것인지 여전히
말하지 않는다. 접힘은 본문의 유무만 정한다.

### 오류가 있으면 접히지 않는다

`errors`가 비어 있지 않으면 접힘을 무시하고 펼친다.

이 규칙이 없으면 이렇게 된다 — 유저가 보스 설정을 접고 계산을 누른다. 필수
입력이 비어 검증이 실패한다. 그런데 오류 문구는 접힌 본문 안에 있다. 화면에는
**아무 이유 없이 계산이 안 되는 것처럼** 보인다.

두 탭 다 `errors={touched ? … : {}}`를 넘기므로 같은 규칙이 그대로 걸린다.

### 접기 컨트롤

legend 안에 `<button aria-expanded aria-controls>`를 둔다. legend에 직접 클릭
핸들러를 달면 키보드로 닿지 않는다.

주의: legend에는 회차가 있을 때 `HelpTip`이 이미 들어 있다. **버튼이 HelpTip을
감싸면 안 된다** — 버튼 안의 버튼은 무효다. 둘은 legend 안에서 형제로 나란히
둔다.

## 9. 테스트

각 항목이 **구현을 망가뜨렸을 때 실제로 빨개지는** 테스트를 갖는다. 「가드를
떼면 실패하는가」에 답할 수 없는 테스트는 아직 아무것도 재지 않는 것이다.

| 항목 | 무엇을 재나 | 망가뜨리면 |
|---|---|---|
| §1 카드 클릭 | 오버로드 `<span>`·스킬레벨 칸에 발생시킨 클릭이 토글/배치를 부르고, 초상화 클릭은 **한 번만** 부른다 | 핸들러를 버튼에 되돌리면 바깥 영역이 안 불리고, 버튼에도 남기면 초상화가 두 번 불린다 |
| §1 우회 가드 | 제외·배치된 칩의 **스킬레벨 칸** 클릭이 배치를 안 부른다 | 껍데기 핸들러에서 `isUsed \|\| isExcluded` 가드를 빼면 `disabled`를 우회해 배치된다 |
| §2 집기·놓기 | 전이표 7행을 각각 | 교환을 이동으로 바꾸면 상대 좌석이 빈다 |
| §2 `Esc` | 든 뒤 `Esc` → 좌석이 그대로 차 있다 | 취소를 제거로 구현하면 좌석이 빈다 |
| §3 제외 차단 | 제외된 칩이 배치 화면에서 `disabled`, 니케 풀에서는 아니다 | `onSeat` 조건을 빼면 니케 풀에서 제외 해제가 막힌다 |
| §4 미란다 | 일부 사이클만 받는 유닛의 **공격력** 뱃지에 `n/T` | 크댐에만 붙이면 빨개진다 |
| §5 저장 이름 | 속성 셋 → `수냉 작열 풍압`, 하나 빔 → `약점없음` 자리 유지 | 건너뛰기로 구현하면 길이가 달라진다 |
| §6 덱 라벨 | 폴백 3단계 각각 + **속성 바꾸면 옛 이름이 안 남는다** | 가드를 빼면 옛 이름이 남는다 |
| §7 상한 경고 | 빈 프로필에 첫 저장 → 경고가 **안** 뜬다 | 현재 코드에서 빨갛다(재현 테스트) |
| §8 접기 | 접으면 본문 필드가 사라지고 머리가 보스 이름이 된다 | 본문을 CSS로만 감추면 필드가 쿼리에 계속 잡혀 빨개진다 |
| §8 오류 강제 펼침 | 접은 뒤 오류가 생기면 오류 문구가 **보인다** | 강제 펼침을 빼면 오류가 접힌 안에 숨어 빨개진다 |

§6의 「속성을 바꾸면 옛 이름이 사라진다」와 §7의 재현 테스트는 **먼저 빨갛게
만들고** 시작한다.

## 10. 레벨 400을 여기서 다루지 않는 이유

`roster_assembly.py`는 `assemble_atk`/`assemble_hp`를 `level=400`으로 **하드코딩**해
부르고, 로스터가 실어 나르는 스탯 블록은 `raid400` 하나뿐이다. 실제 레벨은 바로
위에서 `owned["lv"]`로 이미 뽑아 두고 쓰지 않는다. 그래서 배선만 보면 열려 있다.

열려 있지 않은 것은 **모델의 타당성**이다. `stat_assembly.py`의 상수들은 레벨
400에서 측정된 값에 맞춰 적합된 것이고, 다른 레벨에서도 맞는지는 검증된 적이
없다. 값을 바꿔 끼우는 일보다 **그 값이 맞는지 재는 일**이 본체다.

여기 9건은 전부 프론트엔드이고 그 검증과 아무 관계가 없다. 묶으면 UI 개선이
스탯 검증이 끝날 때까지 발이 묶인다. 별도 스펙으로 뺀다.
