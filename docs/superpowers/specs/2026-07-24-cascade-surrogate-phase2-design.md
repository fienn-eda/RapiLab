# 캐스케이드 대리모델 Phase 2 설계 (탐색 통합)

**Goal:** Phase 1이 검증한 유닛 단독 표본-회귀 대리모델을 `search_best_decks`에
통합해, 후보 조합을 값싸게 랭킹하고 **top-K만 진짜 시뮬**하도록 바꾼다. 기존
`prune_candidate_pool`은 성격이 다른 두 번째 필터로 **남겨** 안전망 역할을 시킨다.

**Architecture:** 백엔드(Python). 신규 `backend/app/cascade.py`가 적합·풀 선정·
조합 랭킹을 맡고, `deck_search.search_best_decks`가 이를 호출한다. `surrogate.py`는
순수 수학(피처·ridge·예측)으로 남는다. 엔진(`raid_simulator`)은 무변경.

**핵심 성질:** 시뮬 비용이 **K에 고정**되고 풀 크기와 무관해진다. 오늘 풀 캡이
11명으로 빡빡한 유일한 이유는 "풀에 들어온 건 전부 시뮬하기 때문"인데, 그 제약이
사라지므로 **풀을 오늘보다 넓히면서도 시뮬은 늘지 않는다.**

---

## 배경 — 무엇이 측정으로 확정됐나

Phase 1 결론(`docs/decisions.md`, 2026-07-24)에 더해, Phase 2 착수 직전 두 가지를
추가 실측했다.

**1. 비용은 한 단계에 몰려 있다** (`scripts/measure_allocation_phase_split.py`,
41유닛·5덱·직렬, 총 8,071 시뮬):

| 단계 | 시뮬 | 비중 |
|---|---|---|
| prune (풀 선정) | 252 | 3.1% |
| **search (풀 조합의 순서 전수 시뮬)** | **7,385** | **91.5%** |
| swap (힐클라임) | 407 | 5.0% |
| summary | 27 | 0.3% |

→ 캐스케이드는 `search`를 쳐야 하고, **prune을 안전망으로 남기는 비용은 3.1%**로
사실상 공짜다. swap은 45초 데드라인으로 이미 묶여 있어 대상이 아니다.

**2. `prune_candidate_pool`은 이미 캐스케이드다.** 참조덱 대비 한계 기여도로 유닛을
값싸게 점수 매겨 `PRUNED_TIER_CAPS = {1:2, 2:3, 3:6}`(11명)으로 자른다. 즉 Phase 2는
캐스케이드를 *도입*하는 게 아니라 **두 번째 단을 얹는** 일이다. 두 필터의 사각지대가
서로 다르다는 점(참조덱 기여도 vs 회귀 계수)이 안전망의 근거다.

**속도 이득 추정치 정정:** 앞서 인용한 78유닛 37x는 prune·swap·summary가 남는 것을
반영하지 않은 수치다. 안전망을 유지하는 이 설계의 추정치는 **~22x**다.

## Non-goals

- **`best_completions`(draft 시드 완성 경로) 통합 아님.** 측정상 지배 비용은
  greedy-peel의 `search_best_decks`였다. 필요하면 별도 측정 후 판단.
- **페어 피처 아님.** fit 비용이 대체 대상과 맞먹어 Phase 1에서 기각(41유닛 1.22x).
- **swap 힐클라임 최적화 아님.** 이미 시간 예산으로 묶여 있다.
- **기능 플래그 아님.** 배포된 서버가 없어 A/B 대상이 없고, 작은 로스터용 전수
  경로가 그대로 남아 자연스러운 폴백이 된다.
- **프론트/API 계약 변경 아님.**

## 데이터 흐름

```
roster
  ├─ prune_candidate_pool  → 11명            (기존 휴리스틱, 시뮬 O(로스터), 안전망)
  └─ 대리모델 계수 상위      → N명            (시뮬 0)
        └─ 합집합 = 넓힌 풀  (WIDE_TIER_CAPS = {1:4, 2:6, 3:12}, 약 22명)
              └─ shape_combinations         (약 11,600 조합)
                    └─ 대리모델 랭킹          (featurize + 내적, 시뮬 0)
                          └─ top-K 조합 → 모든 intra-tier 순서 → _score_batch (진짜 시뮬)
```

랭킹 대상은 **조합(멤버십)**이다. 대리모델 피처가 멤버십뿐이라 한 조합의 모든 순서는
같은 점수를 받으므로, 순서 탐색은 top-K에 대해 **진짜 시뮬이** 수행한다 — Phase 1
하네스의 학습 타깃(조합의 best-ordering 딜)과 정확히 같은 구조다.

## 컴포넌트

### `backend/app/cascade.py` (신규)

책임 세 가지만 갖는다.

- **적합** — 전체 로스터에서 feasible 조합 200개를 고정 시드로 추출하고, 각 조합의
  best-ordering 딜을 시뮬해(`SimPool` 배치, 약 900~1,000 시뮬) 유닛 단독 ridge를
  적합한다(`make_feature_space(..., include_pairs=False)`). 산출은 계수 벡터 +
  slug→열 맵을 담은 작은 모델 객체.
- **풀 선정** — `prune_candidate_pool`의 결과를 먼저 넣고, 남은 자리를 **티어별로**
  대리모델 계수가 높은 순서로 채워 `WIDE_TIER_CAPS`까지 확장한다. 티어별로 채우는
  이유는 합법 덱이 세 티어를 모두 요구하기 때문이다 — 계수를 티어 구분 없이 정렬하면
  한 티어가 굶을 수 있다. 기존 합법성 규칙(variant clash, tier-1 seating)은
  `shape_combinations`가 이미 적용하므로 풀 단계에서 중복 검사하지 않는다.
- **랭킹** — 풀의 조합을 featurize해 한 번의 행렬곱으로 점수화하고 상위 K개를 반환한다.

### `deck_search.search_best_decks` (수정)

`sim_budget` 초과 시 오늘의 "prune → 전수" 대신 위 흐름을 태운다. 시그니처에
대리모델 모델을 받는 선택 인자를 추가한다(기본 None = 필요 시 자체 적합).

### `deck_allocation.allocate_decks` (수정)

peel 루프 **진입 전에 전체 로스터로 한 번** 적합하고, 그 모델을 각
`search_best_decks` 호출에 넘긴다.

### 함께 고치는 낭비

`len(orderings) > sim_budget` 판정을 위해 지금은 **전체 로스터의 모든 순서를 실제로
생성**한다(78유닛에서 수백만 개 — 이전 프로파일의 "부모측 생성 23%"). 개수만 필요하므로
예산을 넘는 즉시 조기 종료하는 카운트로 바꾼다. 우리가 손대는 코드의 명백한 낭비다.

## fit 생애주기와 캐싱

**요청 내 재사용(파라미터).** 유닛 단독 모델은 **가산적**이라 계수가 유닛별이고,
전체 로스터로 적합한 모델이 줄어든 `remaining`의 어떤 부분집합에도 그대로 적용된다.
이 성질 덕분에 peel 5회가 하나의 fit을 공유한다. 캐시 키가 아니라 **명시적 인자로
넘기는** 이유는 `remaining`이 반복마다 달라져 키가 갈라지기 때문이다.

**요청 간 캐시(프로세스 LRU, 상한 8).** 키는 데미지에 영향을 주는 모든 것의 결정론적
해시 — 유닛별(슬러그 정렬) `slug`/`base_stats`/`skill_values`/`weapon_stats`/
`overload_options`, 그리고 `BossProfile`의 모든 필드. 큐브는 슬러그 기준 일괄
가정(`assumed_cube_effects`)이라 slug에 포함된다. 저장하는 건 계수 벡터와 열 맵뿐이라
용량은 무시할 수준이고, **내용 기반 키라 별도 무효화 로직이 필요 없다** — 스킬레벨이나
오버로드가 바뀌면 키가 달라져 자동 재적합된다.

**캐싱이 안전한 근거 두 겹.** (1) 엔진에 RNG가 없어 (로스터 상태, 보스, 고정 시드)가
같으면 fit이 비트 단위로 동일하다. (2) 더 중요하게, **대리모델은 필터일 뿐이고 최종
답은 언제나 진짜 시뮬로 고른다** — 캐시 키에 결함이 있어 잘못된 모델을 써도 후보
선정이 나빠질 뿐, 보고되는 데미지 수치가 틀리지 않는다.

## 폴백과 오류 처리

- **순서 수가 `sim_budget` 이하** → 캐스케이드를 타지 않고 오늘 경로 그대로. 기존
  테스트 대부분(작은 가짜 로스터 + `evaluate_deck` 스텁)이 여기 해당한다.
- **표본 부족** — 로스터가 작아 feasible 조합 200개를 못 뽑으면 오늘의
  "prune → 전수" 경로로 폴백한다.
- **표본 추출 시드는 고정 상수**로 재현성을 보장한다.

---

## 검증 게이트 (구현보다 먼저)

Phase 1의 recall은 **전체 로스터에서 균등 추출한 조합**에서 쟀다. 캐스케이드가 실제로
마주하는 건 **풀에서 나온 조합**이고, 그 안은 이미 걸러진 강한 유닛뿐이라 데미지
분산이 훨씬 좁다(검증 로그의 "무작위 픽 평균 33.4%"라는 격차가 풀 안에는 없다).
**순위 문제가 더 어려워지는 방향**이므로 기존 수치를 그대로 전용할 수 없다.

따라서 **Phase 2의 첫 작업은 코드 통합이 아니라 재측정**이다. 두 축을 함께 본다:
(a) 풀에서 추출한 조합 분포, (b) 78유닛 — recall을 한 번도 재보지 않은 실제 통증 지점.

**K 결정 규칙.** 78유닛·풀 분포·**5시드 이상**에서 `best-of-top-K damage`를 재고,
**중앙값 시드가 100%를 회수하고 최악 시드가 95% 이상인 가장 작은 K**를 채택한다.
**K ≤ 100에서 이를 만족하는 값이 없으면 캐스케이드를 채택하지 않고 오늘 경로를
유지한다** — 게이트는 실패할 수 있으며, 그 결과도 받아들이는 결론이다.

**풀 너비는 `WIDE_TIER_CAPS = {1:4, 2:6, 3:12}`(22명) 고정으로 시작한다.** 약
11,600조합이고 피처 행렬은 11,600 × 43 float ≈ 4 MB, 행렬곱 한 번이라 CPU·메모리
모두 무시할 만하다. recall이 게이트를 통과하지 못할 때만 확대를 재검토한다(노브를
둘 다 동시에 튜닝하지 않는다).

## 테스트

- **품질 회귀 테스트(핵심).** 작은 로스터는 기본적으로 캐스케이드를 우회하므로,
  **`sim_budget`을 작게 넘겨 캐스케이드를 강제**한 실행과 오늘의 전수 실행을 둘 다
  돌려 비교한다. 단언은 **캐스케이드 할당의 합산 딜이 전수 결과의 95% 이상**
  — K 결정 규칙의 최악 시드 기준과 같은 선이라 테스트와 게이트가 어긋나지 않는다.
- **단위 테스트.**
  - 넓힌 풀이 `prune ∪ 대리모델 상위`이고 `WIDE_TIER_CAPS`를 지키는지
  - 랭킹이 정확히 K개를 예측 점수 내림차순으로 내는지
  - 캐시가 같은 (로스터, 보스)에 재적합하지 않고, 스킬레벨이 바뀌면 재적합하는지
  - 표본 부족 시 오늘 경로로 폴백하는지
  - **전체 로스터로 적합한 모델이 부분집합 조합을 채점하는지** (요청 내 재사용의 전제)
  - `sim_budget` 이하 로스터가 캐스케이드를 우회하는지
- **기존 스위트 1215 passed / 3 skipped 유지.**

## 수용 측정

통합 후 `scripts/measure_allocation_phase_split.py`를 재실행해 **`search` 단계가
91.5%에서 무너졌는지**로 이득을 확인한다(전후 비교가 같은 도구로 된다). 78유닛
전체 비용은 `scripts/measure_cascade_budget.py`로 재확인한다.
