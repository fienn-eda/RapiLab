- Date: 2026-07-31
- Status: 착륙 완료 (2026-07-31) — 합계 **1.015x → 1.055x**, ±15% 이내 **21/25 → 19/25**,
  백엔드 기준선 **1672 passed / 3 skipped**. 드러난 과대 항은 `docs/engine-gaps.md`
  **항목 21**로 열었다.
- 관련: `docs/engine-gaps.md`(★ 최상단 항목) · `backend/app/attack_rate.py` ·
  `docs/superpowers/specs/2026-07-31-clip-reload-design.md`

## 배경

엔진은 `재장전 = 파일값 / (1 + s)`를 쓴다. **실측이 이 형태를 기각한다**:
크라운(44.35%) + 프리바티(51.16%) + 렐릭베어 큐브(29.69%) = **125.20%**에서 게임은
재장전이 사라지는데, 역수 형태는 어떤 값으로도 0에 못 간다(1.0초를 0.888초로만
줄인다). 상수를 고쳐 메울 수 있는 오차가 아니라 **식의 모양이 틀린 것**이다.

**맞는 모델은 아핀**(`y = ax + b`)이다 — 버프에 비례해 깎이는 부분과, 무슨 짓을 해도
안 깎이는 고정 구간이 따로 있다.

    재장전 = 데이터파일값 × (1 − s) + 0.148초

Fienn 실측 6점(2026-07-29, 60fps), 최대 잔차 **약 1.1프레임**:

| 유닛 | 무기 | 파일값 | 무버프 | 큐브만(29.69%) | 큐브+프리바티(80.85%) |
|---|---|---|---|---|---|
| 프리바티 | AR | 1.0초 | 1.1667 | 0.8333 | 0.3500 |
| 라피: 레드후드 | MG | 2.5초 | 2.65 | 1.90 | 0.64 |

유닛별로 직선을 맞추면 기울기가 **1.0029 / 2.4835**로 **파일값(1.0 / 2.5)과 일치**한다.
즉 데이터 파일의 재장전 시간은 처음부터 맞았고, 엔진이 그것을 잘못된 방식으로 줄이고
있었다. 남는 **0.148초는 스케일되지 않는 고정 구간**이고, AR·MG에서 같다.

**차지 모션 딜레이와 같은 구조다** — 파일값은 맞고, 그 위에 버프가 안 먹는 구간이
얹혀 있다.

## 결정

### 1. 두 분기를 하나의 식으로 되돌린다

```python
RELOAD_FIXED_SECONDS = 0.148

def reload_time_with_speed(reload_time, reload_speed_percent):
    return max(0.0, reload_time * (1 - reload_speed_percent) + RELOAD_FIXED_SECONDS)
```

음수 가지는 **이미** `파일값 × (1 − s)`였다(밀크의 강제 재장전 −50%가 4초가 아니라
3초라는 실측). 이 수정은 양수 가지를 **같은 규약으로 되돌리는** 일이므로 분기가
사라진다.

**`max(0.0, ...)`는 125.20% 관측을 문자 그대로 만족시킨다** — 재장전이 실제로 0이
된다. 0에 닿는 지점은 `s = 1 + 0.148/파일값`이라 프리바티는 114.8%, 레드후드는
105.9%부터다. 둘 다 125.20%보다 아래이므로 관측과 일치한다.
대안(`max(0, 파일값×(1−s)) + 0.148`, 즉 고정 구간은 남기는 형태)은 0.148초를 남기는데,
**둘을 가르는 측정이 없다.** 하나의 식이 되는 쪽을 택하고 이 사실을 한계로 적는다.

### 2. 파일값의 의미가 바뀐다 — s=0은 더 이상 항등이 아니다

무버프 재장전은 파일값이 아니라 **파일값 + 0.148초**다(프리바티 1.0 → 1.148, 실측
1.1667). 즉 데이터 파일의 `reloadTime`은 "재장전 시간"이 아니라 **"재장전 중 버프로
깎이는 부분"**이다. 이 재해석이 모델의 내용 그 자체이므로, s=0 항등을 고정하던
테스트는 갱신이 아니라 **삭제**한다.

### 3. 고정 구간은 전역이다 (Fienn 결정, 2026-07-31)

상수를 본 두 점(프리바티 +0.167 · 레드후드 +0.150)은 둘 다 탄창 무기이고, **상수가
0으로 읽히는 두 점은 둘 다 차지 무기**다 — 밀크(SR, 강제 재장전 −50% → 정확히
2.0×1.5 = 3.0)와 센티(RL, 클립 1회가 정확히 파일값 0.5초 = 30프레임). 무기군별 상수라는
읽기가 가능하다는 뜻이다.

**Fienn 판정: 전역 상수로 간다.** 두 반례는 9프레임을 놓칠 만큼 거친 판독으로 보고,
문서에 적힌 대로 모든 무기에 붙인다. 결과로 밀크의 앵커는 3.0 → **3.148**이 되며,
그 테스트는 이 판정을 근거로 갱신한다.

### 4. 클립 무기는 손대지 않는다

`user_roster.load_nikke_spec`이 파일값에 분할 수를 **미리 곱해서** 넘기므로
`(0.5 × 3) × (1 − s) + 0.148`이 되어 고정 구간이 **탄창당 한 번** 붙는다. 이는
클립 작업에서 Fienn이 확정한 "장전 n회가 끝난 뒤 딜레이는 1회"와 같은 규약이다.
따라서 접기는 그대로 두고, 그 코드 주석에 걸려 있던 "아핀이 착륙하면 다시 봐야 한다"를
**해소로 갱신**한다.

### 5. 캘리브레이션 악화를 받아들이고 착륙한다 (Fienn 결정, 2026-07-31)

오늘 트렁크에서 다시 잰 값:

| 모델 | 합계 | ±15% 이내 |
|---|---|---|
| 현행 (역수) | 1.0150x | 21/25 |
| **아핀 + 0.148** | **1.0553x** | **19/25** |
| (참고) 아핀, 상수 없음 | 1.0559x | 18/25 |

상수 유무는 캘리브레이션을 거의 안 바꾼다(1.0553 vs 1.0559) — **상수는 모델의 정확성
문제지 캘리브레이션 문제가 아니다.**

악화가 어디에 몰리는지가 이 결정의 근거다:

| 유닛 | 현행 | 아핀 |
|---|---|---|
| mast-romantic-maid | 1.108 | **1.305** |
| helm-signature | 1.243 | **1.346** |
| velvet | 1.074 | **1.205** |
| crown | 1.177 | 1.225 |
| little-mermaid | 1.038 | 1.111 |
| rei-ayanami | 0.936 | **1.008** ✓ |
| scarlet-black-shadow (차지) | 0.999 | 0.999 |

**이미 과대인 유닛이 더 과대해지고 과소인 유닛은 1.0에 붙는다.** 재장전이 빨라지면
평타 발수가 늘어나므로, 숨은 과대 항이 **평타 쪽**에 있다는 신호다. 덱4·덱5는 차지
무기가 많아 거의 안 움직인다.

기각된 식을 합계가 예뻐 보인다고 유지하는 것은 이 프로젝트가 오늘 두 번 기록한
안티패턴이다(택티컬 베어: 흑련을 정확하게 만들자 합계가 1.011 → 1.015로 멀어졌고,
그것이 진전이었다). **합계 1.0 근접은 성공 지표가 아니다.**

## 범위 밖

- **드러난 과대 항 추적** — 별도 작업으로 연다. 이 착륙이 그 신호를 선명하게 만든다.
- 0.148의 재측정, 무기군별 상수(전역으로 확정됨).
- `s > 1`에서 고정 구간이 남는지 사라지는지의 측정.

## 테스트

- **실측 6점 앵커** (신규) — 모델의 근거를 회귀 테스트로 승격한다. 허용 오차는 잔차
  그대로 **±1.2프레임**(0.02초).
- **삭제**: 역수 형태·거울대칭(`f(p)·f(−p) = 파일값²`)·s=0 항등을 고정하던 세 테스트.
  셋 다 모델이 부정하는 성질이라 갱신이 아니라 제거가 맞다.
- **갱신**: 밀크 음수 가지 3.0 → 3.148(결정 3의 판정을 주석으로).
- **신규**: `s = 1 + 0.148/파일값`에서 0에 도달하고 그 아래로 안 내려가는 것.
- **신규**: 클립 무기가 고정 구간을 탄창당 **한 번만** 받는 것(센티 격자).
- 차지창 계산기의 `reload_intervenes` 임계가 움직이므로 그 테스트를 재확인한다.
