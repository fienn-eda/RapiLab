# 창 폭을 쓰는 레이아웃

날짜: 2026-08-02

## 문제

앱이 `max-width: 1120px`에 갇혀 있다. 1920px 창에서는 화면의 42%가 빈 여백이고,
그 좁은 폭 안에서 모든 것이 세로로 쌓인다. Fienn이 짚은 불편은 셋이다.

1. **좌우 여백이 아깝다** — 넓은 창에서 양옆이 텅 빈다.
2. **폼과 결과를 같이 볼 수 없다** — 결과가 유닛 팔레트 아래에 있어, 설정을
   고치려면 위로, 결과를 보려면 아래로 스크롤해야 한다.
3. **니케 풀이 너무 길다** — 로스터 그리드가 한 줄에 6개뿐이다.

여기에 더해 단일/전부 최적화 모드의 실행 버튼이 화면 하단 sticky 바에 붙어
있는 것이 불편했다.

## 설계

### 1. `.app`의 폭 제한 해제

`frontend/src/App.css:5`의 `max-width: 1120px`를 없애고, 좌우 패딩을
`var(--sp-4)`(16px)에서 `var(--sp-5)`(24px)로 키운다. 폭 제한이 사라지면 양끝
여백이 사라지므로 패딩이 그 역할을 대신한다.

이 한 곳만 고치면 아래 요소들은 이미 폭에 반응하도록 짜여 있어 따라온다:

| 요소 | 기존 규칙 | 넓어졌을 때 |
| --- | --- | --- |
| 로스터 그리드 (`.roster__grid`) | `auto-fill, minmax(170px, 1fr)` | 열 수 증가 |
| 유닛 팔레트 (`.palette__list`) | `flex-wrap` | 줄 수 감소 |
| 팔레트\|덱 (`.draft-layout`) | `minmax(0,1fr) minmax(300px,24rem)` | 팔레트 컬럼만 넓어짐 |
| 보스\|모드 (`.recommend-form__setup`) | `minmax(260px,22rem) minmax(0,1fr)` | 모드 컬럼만 넓어짐 |
| 유니온 전투 카드 (`.union-raid-form__battle`) | `flex: 1 1 260px` | 한 줄에 더 많이 |

기존 `@media (max-width: 900px)` 축소 규칙들은 그대로 둔다. 좁은 창의 동작은
바뀌지 않는다.

### 2. 글줄 폭은 따로 제한 — `--measure`

레이아웃은 창을 꽉 채우되, **문장은 읽을 수 있는 길이를 넘지 않는다.**
`frontend/src/index.css`의 `:root`에 토큰을 추가한다:

```css
--measure: 72ch;
```

문장을 담는 블록에만 `max-width: var(--measure)`를 건다:

- `.app__subtitle`, `.app__note`
- `.mode-switch` — 모드 라디오는 각각 문장 길이의 힌트를 달고 있다. 힌트
  `<span>`은 인라인이라 max-width가 듣지 않으므로 컨테이너에 건다.
- `.group__details > summary` — 팔레트 요약문
- `.recommend-form__progress`
- `.raid-results__note`, `.evaluation-results__ordering-note`
- `.deck-results__excluded`, `.raid-results__leftover`
- `.charge-panel__assumption`
- `.empty__text`

`.sync__hint`는 이미 `max-width: 480px`로 일부러 더 좁게 잡혀 있다. 건드리지
않는다.

### 3. 결과를 설정 행 바로 아래로 (전 모드)

진행 중 메시지 · 에러 · 결과 블록을 폼 끝에서 **설정 행 바로 뒤**로 옮긴다.

**`RecommendPanel.tsx`** — 단일/전부 최적화 모드:

```
설정 행 (보스 | 모드)
실행 버튼            ← 4번에서 옮겨옴
진행 중 / 에러 / 결과  ← 여기로 옮김
사용할 유닛 (팔레트)
```

**`RecommendPanel.tsx`** — 빈자리/기대 딜량 모드:

```
설정 행 (보스 | 모드)
진행 중 / 에러 / 결과  ← 여기로 옮김
편성 [팔레트 | 덱(sticky) + 실행 버튼]
```

**`UnionRaidPanel.tsx`**:

```
전투 수 + 전투별 보스 프로필
진행 중 / 에러 / 결과  ← 여기로 옮김
편성 [팔레트 | 덱(sticky) + 실행 버튼]
```

결과 블록이 `<form>` 안으로 들어간다. HTML상 유효하고 제출 동작에 영향이 없다.
폼 밖에 두려면 제출 버튼에 `form=` 속성을 달아 폼을 쪼개야 하는데, 그쪽이
더 복잡하다.

이 배치는 같은 파일이 이미 한 번 받은 처방이다 — `RecommendPanel.tsx:439`의
주석은 보스 필드가 폼 끝에 있던 시절 "답을 가장 크게 움직이는 입력에 아무도
스크롤해 도달하지 못했다"고 적고 있다.

### 4. 단일/전부 최적화 모드의 실행 버튼을 설정 행 아래로

`.recommend-form__actions--sticky`(하단 고정 바)를 없애고, 버튼을 설정 행 바로
뒤·결과 앞에 일반 배치한다. `App.css:948-960`의 규칙과 그 음수 마진 / `z-index: 3`
처리도 함께 삭제한다. 그 규칙이 존재한 이유(70여 개 칩의 팔레트가 버튼을 화면
밖으로 밀어냄)가 버튼이 위로 올라가면서 사라지기 때문이다.

**빈자리 / 기대 딜량 / 유니온 모드는 그대로 둔다.** 이 모드들의 버튼은 sticky
덱 컬럼(`.draft-layout__decks`)에 얹혀 있어 이미 항상 화면에 보인다. 위로
올리면 유닛을 드래그하다 실행할 때마다 스크롤해 올라가야 한다.

## 하지 않는 것

- **결과를 오른쪽 컬럼으로 분리** — 검토했으나 기각. `docs/insights.md`에 이미
  기록된 대로 뷰포트보다 큰 컬럼에는 `position: sticky; top:`이 듣지 않아,
  덱 5개짜리 결과는 어차피 같이 보이지 않는다.
- **결과가 나오면 팔레트 자동 접기** — 검토했으나 기각. 결과를 위로 올리면
  같은 목적을 달성하면서, 접기 상태 관리(컴포넌트 + 훅 + "사용자가 직접
  폈는가" 추적)가 통째로 필요 없고 팔레트의 제외 토글도 살아 있다.
- **덱 결과 카드를 가로로 배치** — 요청에 없다.
- **설정 행 재설계** — 3440px 같은 초와이드에서는 보스 컬럼(22rem 고정)과 글줄
  제한이 걸린 모드 컬럼 오른쪽에 빈 공간이 남는다. 그리드와 결과는 꽉 차므로
  이번 범위 밖으로 둔다.

## 열어두는 결정

없음. 아래 검증에서 문제가 보이면 그때 기록한다.

## 검증

- `cd frontend && npm test` — 기준선은 49개 파일 464 통과 (2026-08-02 이
  워크트리에서 실측). DOM 순서에 의존하는 테스트가 있으면 순서 기대만 고친다.
  테스트를 삭제하거나 축소하지 않는다.
- 백엔드 + 프론트를 띄우고 실제 로스터로 세 폭에서 눈으로 확인한다:
  - **1920px** — 주 대상. 팔레트/로스터 열 수, 글줄 길이, 결과 위치
  - **1400px** — 중간
  - **900px 이하** — 기존 축소 규칙이 그대로 도는지 (회귀 확인)
- 확인할 것: 로스터 탭 열 수 증가 / 실행 버튼이 설정 아래 / 결과가 팔레트 위 /
  긴 힌트 문장이 한 줄로 늘어지지 않음 / 빈자리·유니온 모드의 덱 컬럼 sticky
  동작 유지.
