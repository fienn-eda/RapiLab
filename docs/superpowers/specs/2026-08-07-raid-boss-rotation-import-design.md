# 레이드 회차 보스 가져오기 — 설계

날짜: 2026-08-07

솔로 레이드 / 유니온 레이드 공지에서 이번 회차 보스를 읽어 앱의 보스 설정에 반영한다.
Fienn의 요청은 두 겹이다(2026-08-07):

1. 공지에 실린 정보로 보스 프로필을 채울 수 있게 할 것.
2. **「공지 URL을 주면 앱이 갱신된다」를 하나의 워크플로우로** 만들 것.

## 배경 — 공지가 실제로 담고 있는 것

설계 전에 공지 4건을 실제로 열어 읽었다(blablalink 유니온·솔로, arca.live 유니온·솔로).

### 본문에는 보스 정보가 없다

네 건 모두 보스 정보는 **이미지 한 장** 안에 있고, 본문 텍스트에는 보스 이름과 기간
정도만 있다(유니온은 이름조차 없다). 본문 컨테이너는 호스트마다 하나이고, 그 안의
이미지는 **정확히 1장**이다.

| 호스트 | 본문 컨테이너 |
|---|---|
| `blablalink.com` | `.ql-editor` |
| `arca.live` | `.fr-view.article-content` |

페이지 전체에서 `img`를 긁으면 사이드바·추천글·댓글 스크린샷이 섞인다. 조사 중 이걸로
두 번 헛짚어 엉뚱한 이미지를 읽었다. 컨테이너 스코프가 그 재발 방지책이다.

### 유니온 레이드 — 2026-07-31 회차

보스 5기, 5속성이 하나씩. 카드 레이아웃은 완전히 고정형이다.

| 이름 | 영어판 | 등급 | 약점 | 거리 |
|---|---|---|---|---|
| 선바스 | SUNBATHER | 로드 급 | 전격 | 근거리 |
| 플레이트 | PLATE | 로드 급 | 작열 | 원거리 |
| 토커티브 | CHATTERBOX | 타이런트 급 | 수냉 | 원거리 |
| 리빌드 핑거즈 | REBUILD FINGERS | 로드 급 | 풍압 | 원거리 |
| 마테리얼 H | MATERIAL H | 타이런트 급 | 철갑 | 근거리 |

각 카드에는 2줄짜리 설명 산문이 붙는다.

### 솔로 레이드 — 시즌 39

보스 1기이고, **유니온과 항목이 다르다.**

| 항목 | 값 |
|---|---|
| 이름 | 아일랜드 이터 (본문 텍스트에도 있음) |
| 진행 기간 | 7/16(목) 12:00 ~ 7/23(목) 4:59 |
| 보스 속성 | 전격 |
| 약점 속성 | 철갑 |
| 스쿼드 추천 | 머신건 니케 |
| 랩쳐 주요 공격 | 3개 항목. 그중 *"호밍 레이저는 … 저지 부위를 공격해 방어하세요"* |

즉 두 레이드의 **공통 항목은 보스 이름과 약점뿐**이다. 유니온만 거리·등급을 주고,
솔로만 보스 속성·스쿼드 추천·공격 패턴을 준다.

### `BossProfile` 8필드와의 대조

| 필드 | 유니온 | 솔로 |
|---|---|---|
| `element` (약점에서 역산) | ✅ | ✅ |
| `effective_range_band` | 「거리: 근/원」 — 대응 미확인 | ❌ |
| `core_hittable` | ❌ | ❌ |
| `part_destructible` | ❌ | ❌ (아래 참고) |
| `pierce_hits_body_behind_core` | ❌ | ❌ |
| `elemental_interrupt_required` | ❌ | ❌ |
| `enemy_def` | ❌ | ❌ |
| `fight_duration` | ❌ | ❌ |

### 조사에서 같이 확인된 것 셋

**`elements.py`가 공식 데이터로 검증됐다.** 솔로 공지가 보스 속성 = 전격, 약점 = 철갑을
나란히 적어 두었고, `weakness_of("Electric")`이 `"Iron"`을 낸다. 유니온 공지는 약점만
적어서 이 대조가 불가능하다 — 솔로 공지가 매 시즌 무료로 주는 검증 지점이다.

**`part_destructible`은 보스의 사실이 아니다.** 도움말이 *"파츠파괴에 의존하는
유닛(예: 아크레인저 블랙)의 최대 잠재력 모델을 선택해요. 체크 해제 시 하한 모델"* 이라고
적고 있다. 모델링 선택이지 보스 속성이 아니므로, 공지가 「저지 부위」를 뭐라 적든 이
플래그가 여기서 나올 수 없다.

**한국어판이 이름을 정한다.** CHATTERBOX의 한국 서버 공식 이름은 **「토커티브」**다.
영어판을 읽고 음차하면 "챗터박스"가 나오는데 그건 존재하지 않는 이름이다.
`display_names.py`가 지키는 원칙(한국 서버 공식 표기, 음차 아님)이 여기서도 그대로
걸린다.

## 결정

### D1. 이미지는 앱이 아니라 워크플로우가 읽는다

데이터가 전부 이미지 안이라, 앱이 URL을 받아 파싱하려면 앱이 OCR을 들고 다녀야 한다
(Tesseract 동봉 / 비전 API 키 / 글자·아이콘 템플릿 매칭). 필드 몇 개를 위해 무겁고,
공지 디자인이 바뀌면 깨진다.

대신 Fienn이 URL을 주고 **에이전트가 이미지를 읽어 데이터 파일로 커밋**한다. 앱은 그
파일만 읽는다. 이 저장소가 `/collect-nikke`, `/onboard-new-nikkes`로 이미 쓰고 있는
방식이다.

**결과: 앱에 이미지 처리 코드가 0줄 들어간다.**

### D2. 어떤 값도 상속되지 않는다

> 동일 보스더라도 시즌마다 속성이 바뀌어서 등장할 때가 많아. 과거 시즌의 데이터로 인해
> 현재 시즌 보스의 데이터가 잘못 입력되는 일은 없어야 해. — Fienn, 2026-08-07

따라서 데이터 파일의 키는 **보스 이름이 아니라 (회차, 보스)** 다. 「선바스는 코어가
있다」 같은 기록이 구조적으로 시즌을 넘어갈 수 없어야 한다.

같은 원칙이 세션 안에서도 걸린다: 보스 카드를 고르면 공지가 준 값 외의 필드는 **기본값으로
초기화**된다. 직전에 고른 보스의 설정이 남으면 화면에는 「플레이트」라고 적혀 있는데
계산은 「토커티브」 가정으로 도는 상태가 되고, 그건 D2가 막으려는 바로 그 실패다.

### D3. 명시된 것만 자동 입력하고, 추론은 원문으로 보여준다

**자동으로 채워지는 값은 약점 속성 하나뿐이다.** 나머지는 공지 원문을 카드 옆에 그대로
띄우고, 체크는 Fienn이 한다.

자동화하지 않는 것과 그 이유:

- **「거리: 근거리/원거리」** — 우리 `effective_range_band`는 Ade: Agent Bunny 실측에서
  나온 3단계(near/mid/far)인데, 공지에서 관측된 값은 근/원 둘뿐이다. 게임의 「거리」가
  2단계인지 3단계인지 모르는 상태에서 매핑하면 틀릴 수 있다.
- **「스쿼드 추천: 머신건 니케」** — 우리 mid 밴드가 AR·MG를 지불하긴 하지만, MG 추천이
  거리 때문인지 지속사격 때문인지 공지는 말하지 않는다.
- **「저지 부위」** — `part_destructible`은 위에서 본 대로 보스의 사실이 아니다.

틀린 매핑은 값 검증을 전부 통과하고 조용히 초록으로 남는다. 이 저장소는 그 실패를 이미
두 번 겪었다(`▼` 부호 오류, 팬텀 애장품 스택 문구). 판독의 근거가 화면에 원문으로
남아 있으면 나중에 되짚을 수 있다.

### D4. 한국어 공지를 1순위로 한다

토커티브 때문이다. 영어 공지를 읽으면 한글 이름을 우리가 만들어야 하고, 그 순간 음차가
된다. 속성명도 한국어판이 전격·작열·수냉·풍압·철갑을 그대로 준다.

blablalink(영어)도 지원하되, 한국어판이 있으면 그쪽을 쓴다.

### D5. 이미지 URL은 보관하지 않는다

arca.live 이미지는 **서명 URL이고 만료된다** — 관측된 만료는 발급 후 약 10시간이었다
(`expires=1786070129` → 2026-08-07 11:35). blablalink CDN URL에는 만료가 없다. 두
호스트를 한 스키마로 담으려면 만료되는 쪽을 기준으로 잡아야 한다.

글 주소(`source_url`)만 남기고, 이미지는 판독할 때 받아서 버린다. 다시 볼 일이 있으면
글을 다시 연다.

## 설계

### 1. 데이터 파일 — `data/raid-rotations.json`

여기 두는 이유: 최상위 `data/`는 gitignore 대상이 아니라 커밋되고
(`data/nikke-stat-tables/`가 이미 그렇게 있다), `packaging/rapilab.spec:19`가 `data/`
전체를 앱 번들에 넣는다. 얼린 앱에서도 `paths.data_dir()`로 읽힌다.

```json
{
  "schema_version": 1,
  "rotations": [
    {
      "id": "union-2026-07-31",
      "raid": "union",
      "title": "유니온 레이드 7/31",
      "starts_at": "2026-07-31T05:00:00+09:00",
      "ends_at": "2026-08-06T04:59:00+09:00",
      "source_url": "https://arca.live/b/nikketgv/177833660",
      "source_locale": "ko",
      "read_on": "2026-08-07",
      "bosses": [
        {
          "name": "선바스",
          "weakness": "Electric",
          "stated": {
            "등급": "로드 급",
            "약점": "전격",
            "거리": "근거리",
            "설명": [
              "머리에 불길한 꽃을 얹고 있는 지상형 랩쳐.",
              "꽃봉오리 가득 에너지를 모아 앞으로 쏘아댄다."
            ]
          }
        }
      ]
    }
  ]
}
```

필드:

- `id` — 회차 식별자. 솔로는 `solo-<시즌번호>`, 유니온은 `union-<시작일>`(유니온 공지에는
  시즌 번호가 없다). 같은 `id`로 다시 넣으면 교체한다.
- `raid` — `"solo"` | `"union"`.
- `starts_at` / `ends_at` — KST 오프셋을 명시한 ISO 8601. 읽은 공지 4건은 이미지에
  시작·종료를 다 적고 있었지만, arca 솔로 글의 **본문 텍스트**는 종료만 적었다. 이미지를
  못 읽고 본문만으로 들어오는 경로가 있으므로 `starts_at`은 `null`을 허용한다.
- `source_locale` — `"ko"` | `"en"`. `name`이 어느 표기인지 읽는 쪽이 알아야 한다.
- `read_on` — 판독한 날. 공지 게시일이 아니다.
- `bosses[].weakness` — **기계가 읽는 유일한 필드.** 공지의 약점을 엔진 어휘
  (`Fire`/`Water`/`Wind`/`Iron`/`Electric`)로 옮긴 값이다. **비워둘 수 없다** —
  로더가 거부한다(Fienn, 2026-08-07). 앱의 보스 설정은 「약점 없음」을 지원하고
  엔진도 무속성 보스를 다루지만, 공지 경로에서는 약점 없는 보스를 받지 않는다.
  카드를 고르면 채워지는 값이 약점 하나뿐이라, 그 하나가 비면 카드를 눌러도
  화면에 아무 일도 안 일어난 것처럼 보이면서 나머지 7개 필드는 조용히 초기화된다.
  그런 회차가 실제로 나오면 그때 로더가 터지고, 우리는 무엇을 어떻게 표시할지
  정한 뒤에 열면 된다.
- `bosses[].stated` — 공지 원문. `key → string | string[]`의 자유 형식이다. 유니온과
  솔로가 서로 다른 항목을 갖는 것을 스키마 분기 없이 담고, 공지 디자인이 바뀌어도
  파일이 깨지지 않는다. **여기 있는 값은 앱이 해석하지 않는다 — 화면에 그대로 띄우기만
  한다.**

`weakness`를 담고 `element`(보스 본인 속성)를 담지 않는 이유: 프론트에 이미
`bossElementFor(weakness)` 변환 지점이 하나 있다(`BossProfileField.tsx:78`). 파일에
역산된 값을 넣으면 변환 지점이 둘이 되고, 그중 하나가 반대로 틀려도 값 검증은 통과한다.
파일에는 공지가 적은 것만 들어간다.

### 2. 워크플로우 — `/update-raid-bosses <URL>`

**`.claude/skills/update-raid-bosses/SKILL.md`에 스킬로 놓는다.**
`.claude/commands/*.md`가 아니다: 기존 커맨드 셋은 전부 `context: fork`로 서브에이전트에
넘기는 한 방짜리인데(`collect-nikke`·`document`·`test-engine`), 이 워크플로우는 3단계에
Fienn 확인 게이트가 있고 포크된 서브에이전트는 Fienn에게 닿지 못한다. 사람 게이트가 있는
다단계 절차는 `onboard-new-nikkes` 스킬과 같은 자리에 속한다.

인자는 **공지 글 URL 또는 이미지 URL 직접** 둘 다 받는다. 호스트 셀렉터가 안 먹거나
새 사이트가 나와도 이미지 주소만 주면 우회된다. 2단계 이후가 동일해서 공짜다.

1. **본문 추출** — 글 URL이면 브라우저로 열어 호스트별 컨테이너 안의 이미지 URL과 본문
   텍스트를 뽑는다(위 표). 이미지 URL이면 이 단계를 건너뛴다.
2. **판독** — 이미지를 받아 보스 카드를 읽는다. 솔로처럼 보스 속성과 약점이 같이 적혀
   있으면 `weakness_of(보스속성) == 약점`을 대조하고, 어긋나면 멈춘다.
3. **사람 게이트** — 판독 결과를 표로 Fienn에게 보여주고 확인받는다. 워크플로우의 유일한
   중단점이다.
4. **파일 갱신** — `data/raid-rotations.json`에 회차를 추가한다. 같은 `id`면 교체.
5. **커밋**

### 3. 백엔드 — `GET /api/raid-rotations`

`app/raid_rotations.py`가 파일을 읽어 검증하고, `api.py`가 라우트로 낸다.
`app/supported_units.py` + `/api/supported-units`와 같은 모양이다.

검증(로드 시점):

- `id` 중복 없음
- `weakness`가 5속성 중 하나이거나 `null`
- `starts_at`/`ends_at`이 파싱되고, 둘 다 있으면 `starts_at < ends_at`
- `raid`가 `solo`/`union` 중 하나

응답은 파일 내용을 그대로 낸다. 회차 선별(최신만 노출)은 클라이언트가 한다 — 서버가
자르면 과거 회차를 보려는 다음 요구가 생겼을 때 양쪽을 고쳐야 한다.

### 4. 프론트 — 회차 보스 피커

`BossProfileField` 위에 놓는다. 회차 데이터가 없으면 아무것도 그리지 않는다.

- 노출 대상은 **레이드 타입별 최신 회차 하나**이고, 최신은 `ends_at`이 가장 늦은
  회차로 정한다(배열 순서나 `read_on`이 아니다 — 둘 다 뒤늦게 넣은 과거 회차에
  뒤집힌다). 지난 시즌 값이 눈에 띄어 잘못 쓰이는 경로를 만들지 않는다(D2).
- 유니온 탭은 3전투 각각이 5보스 중 하나를 고르고, 솔로 탭은 시즌 보스 1장이다.
- 카드를 고르면:
  - `element`에 `bossElementFor(boss.weakness)` — 자동으로 채워지는 유일한 값
  - **나머지 6개 필드는 기본값으로 초기화** (D2)
  - `stated`를 카드 옆에 원문 그대로 표시 — Fienn이 그걸 보면서 나머지를 체크한다

### 5. 테스트

백엔드:

- 검증 규칙 각각에 대해 깨진 파일이 거부되는지
- `/api/raid-rotations`가 파일 내용을 그대로 내는지

프론트:

- 카드를 고르면 `element`가 약점에서 역산된 값으로 들어가는지
- **다른 필드를 손으로 켜 둔 상태에서 카드를 고르면 그 필드가 초기화되는지** — D2를
  못박는 테스트다. 이게 없으면 "안 건드리는" 구현이 조용히 통과한다.
- 회차 데이터가 비었을 때 피커가 안 그려지는지
- `stated`의 값이 해석되지 않고 그대로 렌더되는지

## 범위 밖

- **OCR·비전 API·이미지 처리 코드** — D1에서 앱 밖으로 뺐다.
- **자동 감지나 주기 실행** — Fienn이 URL을 줄 때만 돈다. 신규 니케 감지와 달리 회차는
  드물고, 잘못 읽은 회차가 조용히 들어가는 쪽이 나쁘다.
- **보스별 카탈로그** — 「선바스는 코어가 있다」를 시즌 너머로 재사용하는 구조. D2가
  금지한다.
- **거리·부위파괴 등 나머지 6필드의 자동 입력** — D3. 의미가 확인되면 각각 한 줄
  변경으로 열 수 있다.
- **유니온 레이드 추천**(엔진이 3덱을 직접 구성) — 이 작업과 무관하게 이미 범위 밖이다
  (`docs/roadmap.md`).
