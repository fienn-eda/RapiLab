# UI 다듬기 + 동기화 탭 분리 — 설계

- Date: 2026-08-01
- Status: 승인됨 (Fienn)
- 배경: Fienn이 설치된 앱을 켜고 짚은 6건 + 그 조사에서 드러난 동기화 버그 1건

## 배경

Fienn이 `dist/RapiLab/RapiLab.exe`를 실행해 화면을 보며 개선점을 짚었다. 그중
계정 드롭다운이 UID로 뜬다는 건은 북마크릿을 다시 설치하니 해소됐고(설치된
북마크릿이 닉네임을 읽기 전 버전이었다), 대신 **부계정 동기화가 앱에 도달하지
않는** 문제가 드러났다 — 브라우저는 "로스터를 보냈어요"까지 띄우는데 앱의 계정
드롭다운에는 본계정만 남아 있었다.

## 결정

### 1. 폴링 게이트는 진행 중일 때만 닫는다

`useBookmarkletImport`의 인박스 폴링은 `status !== 'idle'`이면 멈춘다. 그런데
`'done'`(성공)과 `'error'`(실패)에서 `idle`로 돌아가는 경로가 없어, 한 번
동기화가 끝나면 폴링이 영구히 멈춘다.

첫 동기화가 성공하는 건 우연에 기댄다. `App.tsx`는 활성 프로필 유무에 따라
`SyncRosterPanel`을 삼항의 서로 다른 가지에서 그리므로, 첫 계정이 생기는 순간
컴포넌트가 통째로 갈아끼워지며 상태가 `idle`로 리셋된다. **활성 프로필이 이미
있는 상태에서의 동기화는 그 리셋을 받지 못한다** — 부계정이 앱에 닿지 못한
경로이고, 같은 이유로 재동기화도 앱 실행당 한 번만 가능하다.

주석이 밝히는 게이트의 의도는 "후보를 고르는 중이거나 조립 중에 새 payload가
끼어들면 안 된다"이다. 그 의도가 지켜야 할 상태는 `choosing`과 `importing`뿐이므로
게이트를 그 둘로 좁힌다.

```js
if (status === 'choosing' || status === 'importing') return
```

`done`/`error`에서 폴링이 재개돼도 인박스는 이미 비어 있어 아무 일도 일어나지
않는다. 새 payload가 오면 `handle`이 `setError(null)`로 시작하므로 앞선 실패
메시지도 함께 정리된다.

### 2. 동기화는 자기 탭을 갖는다

`SyncRosterPanel`을 니케 풀 탭에서 꺼내 `TABS` 맨 뒤의 새 탭으로 옮긴다. 맨 뒤인
이유는 동기화가 가끔 하는 일이기 때문이다 — 앞자리는 매번 쓰는 탭이 갖고, 계정
전환은 헤더 드롭다운에 항상 떠 있어 접근성이 줄지 않는다.

탭 패널은 전부 마운트된 채 `hidden`으로만 감춰지므로(레이드 요청이 탭 전환에
취소되면 안 된다) **폴링은 어느 탭에 있든 계속 돈다**. 결정 1과 합쳐지면 앱이
켜져 있기만 하면 북마크릿이 언제든 닿는다.

### 3. payload가 도착하면 동기화 탭으로 전환한다

한 계정이 여러 서버에 로스터를 가지면 "어느 서버를 가져올까요?" 선택 버튼이
뜬다. 그 질문이 감춰진 패널 뒤에 있으면 유저는 영영 볼 수 없고, 동기화는 조용히
멈춘 것처럼 보인다. 그래서 `SyncRosterPanel`이 payload를 받아들인 순간
`onActivity`를 올리고 `App`이 탭을 바꾼다.

후보가 하나뿐이라 바로 조립되는 흐름에서도 전환한다 — 결과("N기 동기화됨")와
경고 줄이 그 패널에만 있으므로, 전환하지 않으면 유닛이 미지원이라는 안내가
아무에게도 닿지 않는다.

### 4. 보스 설정 도움말은 호버 툴팁으로

보스 설정의 설명 세 개(적정거리·코어 피격·부위파괴)가 항상 펼쳐져 있어 폼이
길어진다. 라벨 우측의 `?` 버튼에 넣고 마우스를 올렸을 때만 보이게 한다.

표시는 CSS `:hover`/`:focus-visible`만으로 한다. 클릭 토글을 두지 않는 이유는
키보드 포커스로 이미 열 수 있고, 고정 기능을 원한다는 요구가 없기 때문이다.

세 개를 한꺼번에 옮기는 이유는 스크롤 길이의 원인이 이 세 덩어리라서다. 하나만
옮기면 절반만 짧아진다.

### 5. 도움말 문구는 한 파일에 모은다

`frontend/src/lib/helpText.ts`가 안내 문구를 갖고, 컴포넌트는 그것을 참조한다.
Fienn이 컴포넌트 코드를 열지 않고 문구만 고칠 수 있어야 한다.

문구에는 강조가 필요한 곳이 있어 `**강조**`만 `<strong>`으로 바꾸는 렌더러를
함께 둔다. 마크다운 파서를 들이지 않는 이유는 필요한 표현이 강조 하나뿐이고,
문구가 사용자 입력이 아니라 우리가 쓴 상수라 임의 HTML을 다룰 위험이 없어서다.

단위 표시("초", "%")와 에러 메시지는 옮기지 않는다. 앞쪽은 라벨의 일부이고,
뒤쪽은 안내가 아니라 상태 보고라 문구 파일에 섞이면 무엇을 고쳐도 되는지가
흐려진다.

### 6. 동기화 안내는 실제 흐름을 적는다

`SyncHelp`의 4~5단계는 링크를 북마크 바로 드래그하라고 안내하지만, 앱은 네이티브
창이라 북마크 바가 없다. 패널이 실제로 제공하는 것은 "북마크릿 주소 복사"
버튼이다. 안내를 그 흐름으로 다시 쓴다.

`SyncRosterPanel`의 버튼 옆 인라인 힌트는 **남긴다**(Fienn 지정). 같은 절차를
두 번 말하지만, 하나는 전체 흐름이고 하나는 버튼을 누르는 순간의 맥락이다.

### 7. 오버로드 옵션명과 정렬 기본값

`.overload__name`이 `--text-muted`(#9c95ab)라 어두운 배경에서 잘 읽히지 않는다.
`--text`(#eceaf1)로 올린다. 값과의 구분은 굵기(600)가 계속 맡는다.

`EMPTY_FILTER`의 정렬 기본값을 우코 내림차순으로 바꾼다. 필터는 저장되지 않고
매번 이 상수에서 시작하므로 여기만 고치면 된다.

## 범위

**포함**

- `frontend/src/hooks/useBookmarkletImport.ts` — 폴링 게이트를 좁힌다.
- `frontend/src/components/SyncRosterPanel.tsx` — `onActivity` prop 추가.
- `frontend/src/App.tsx` — `TABS`에 `sync` 추가, 패널 이동, `onActivity`로 탭 전환.
- `frontend/src/components/HelpTip.tsx` — 새 컴포넌트.
- `frontend/src/components/BossProfileField.tsx` — 설명 세 개를 `HelpTip`으로.
- `frontend/src/lib/helpText.ts` — 새 파일. 문구 + `**강조**` 렌더러.
- `frontend/src/lib/unitFilter.ts` — `EMPTY_FILTER` 기본 정렬.
- `frontend/src/components/SyncHelp.tsx` — 문안 재작성.
- `frontend/src/App.css` — `.overload__name` 색, `HelpTip` 스타일, 탭 관련 조정.

**제외**

- 계정 드롭다운의 프로필 이름 직접 편집. 북마크릿 재설치로 닉네임이 정상화돼
  필요가 사라졌다.
- 동기화 안내의 중복 정리(결정 6).
- 앱 안에서 도움말 문구를 편집하는 UI. 저장소·초기화·기본값 관리가 따라붙는데,
  파일 한 곳에 모으는 것으로 Fienn의 요구가 충족된다.

## 문안

동기화 안내가 서술할 실제 절차:

> **동기화 방법**
>
> 1. blablalink **SHIFTYPAD** 페이지 우측 상단의 공유 아이콘을 눌러요.
>    `[shiftypad-share-button.png]`
> 2. **링크 복사하기**를 눌러 URL을 복사해요. `[shiftypad-copy-link.png]`
> 3. 복사한 URL을 아래 칸에 붙여넣어요.
> 4. 나타나는 **북마크릿 주소 복사** 버튼을 눌러요.
> 5. 브라우저에서 북마크를 새로 만들고, **주소(URL) 칸에 붙여넣어요**.
> 6. RapiLab을 켜 둔 채, blablalink에 로그인한 상태로 그 북마크를 눌러요.
>    로스터가 이 화면으로 바로 들어와요.
>
> **다시 동기화할 때**
> 북마크만 다시 누르면 돼요. 공유 URL을 또 붙여넣을 필요는 없어요. RapiLab이
> 켜져 있어야 해요.
>
> **계정이 여러 개일 때**
> 계정마다 북마크가 따로 필요해요 — 북마크릿에는 그 계정의 ID가 들어 있어요.
>
> 1. 추가할 계정의 SHIFTYPAD에서 공유 URL을 복사해 위 1~5단계를 다시 해요.
> 2. 북마크 이름을 계정 이름으로 바꿔두면 어느 계정 것인지 헷갈리지 않아요.
> 3. **그 계정으로 blablalink에 로그인한 상태에서** 해당 북마크를 눌러요.
>
> 동기화한 계정은 위쪽 **계정** 드롭다운에서 전환해요. 계정별 로스터와 추천
> 결과는 섞이지 않아요.
