# 유닛 표시 이름 한글화 + 애장품 하트 — 설계

- Date: 2026-07-25
- Status: 승인됨 (Fienn)
- 관련: `docs/roadmap.md` To-Do "표시 이름이 변형을 구분하지 못한다"

## 배경

한국 유저 대상 서비스로 가기로 정해졌다. 현재 앱은 언어가 섞여 있다 — 오버로드 라벨은
한글(`overload_effects.py`의 `NAME_TO_STAT`, 프론트는 '공'·'크댐'으로 축약까지 한다),
UI 크롬과 유닛 이름은 영문(lootandwaifus 캐릭터 데이터에서 온다).

유닛 이름은 그와 별개로 **버그도 있다**. `/api/supported-units`의 96개 엔트리 중
**17개 이름이 서로 겹친다**. 이름은 캐릭터를 가리키는데 변형을 구분하는 정보는 슬러그에만
있기 때문이다. 다만 겹치는 17건이 다 같은 문제는 아니다:

- **모드 변형(4종)은 진짜 중복이다.** 로스터가 두 후보를 **둘 다** 싣는다(실측: Fienn
  로스터 77 spec에 `bready-lingering`과 `bready-recommended`가 함께 있다). 그래서 벤치에
  "Bready, Bready"가 나란히 뜬다.
- **애장품(`-signature` 13종)은 중복이 아니다.** 로스터는 둘 중 하나만 싣는다(실측:
  `helm-signature`만 있고 맨 `helm`은 없다). 문제는 "지금 애장품 빌드로 돌고 있다"는
  정보가 화면에 안 보인다는 것이다.

## 조사 결과: 한글 이름을 자동으로 들여올 곳은 없다

blablalink는 사이트 UI로는 한국어를 지원하지만(JS 번들에 "한국어", 커뮤니티 글은 한글)
**니케 디렉토리와 캐릭터 데이터는 영문 전용**이다. 세 가지 언어 지렛대를 모두 시도해
196행 전부 영문이었고, ShiftyPad 페이지 본문에 한글이 한 글자도 뜨지 않았다:

| 방식 | 결과 |
|---|---|
| `Accept-Language: ko-KR` | 한글 0 / 196 |
| `lang`·`locale` 쿠키 | 한글 0 / 196 |
| `/ko/` 경로 | 한글 0 / 196 |

`name_localkey`에 키가 `name` 하나뿐이라 로케일 변형 자체가 없다. 따라서 이름은
**Fienn이 직접 작성**한다.

## 결정

### 1. 이름 표는 `backend/app/display_names.py`

슬러그 → 한글 이름 딕셔너리 하나. `.py`인 이유:

- `data/`는 gitignore라 커밋되지 않는다(워크트리에서는 아예 없다).
- 이 저장소는 이미 한글 문자열 표를 `.py`로 갖고 있다(`overload_effects.py`). 큰 표를
  모듈 상수로 두는 것도 기존 방식이다(`registry.py`의 `MODE_VARIANTS`).
- JSON과 달리 주석을 달 수 있다 — 모드 변형처럼 "왜 이렇게 구분했는지"가 필요한 자리가 있다.

값이 빈 문자열이면 아직 안 채운 것으로 보고 영문으로 떨어진다. 즉 **표는 처음부터
완전할 필요가 없고**, 채우는 만큼 한글이 된다.

### 2. 모드 구분은 표에 직접 쓴다 (Fienn)

`"bready-lingering": "브레디 (잔류)"`처럼 통째로 쓴다. 접미사→한글 매핑표도, 파생
로직도 만들지 않는다. 문구를 Fienn이 완전히 통제한다.

### 3. 애장품은 이름이 아니라 하트로 표시한다 (Fienn)

- 초상화에 **주황 하트 뱃지**
- 이름 옆에도 하트
- 대상은 **유저가 실제로 애장품을 장착한 유닛** — `-signature` 인코딩이 있는 13기가
  아니라, 수집기가 유닛별로 내려주는 `favorite_item` 플래그가 참인 모든 유닛.

`favorite_item`은 지금 `rosterImport`가 슬러그를 고르는 데만 쓰고 버린다. `grade`·`core`와
**똑같은 패턴**으로 `NikkeDraft`에 옵셔널 필드로 남긴다 — 와이어 타입(`UserNikkeState`)에는
넣지 않는다(`docs/insights.md`: "UserNikkeState에 UI 편의 필드를 더하지 말 것").
`App.tsx`의 `investmentFor(slug)`가 이미 로스터 옆에서 `{grade, core}`를 팔레트까지
날라주므로 거기에 필드 하나만 더한다 — 새 배선이 없다.

## 범위

**포함** — 지원 96개 슬러그의 한글 이름, 모드 변형 구분, 애장품 하트(뱃지 + 이름).

**후속으로 분리** (Fienn 승인):
- 엔진 미지원 ~86기. `supported-units`에 없어 이 경로로 덮이지 않는다. 96개를 채운 뒤
  별도로 다룬다.
- UI 크롬 한글화("Boss profile", "Recommend decks" 등). 별개 작업.

## 테스트

- 표의 모든 키가 실재하는 슬러그다 (오타 방지)
- **한 캐릭터의 모드 후보들끼리** 이름이 다르다 — 구분 안 하고 넣으면 여기서 잡힌다
- **서로 다른 캐릭터**가 같은 이름을 갖지 않는다 (오타 방지)
- `supported_units()`가 표의 이름을 영문보다 우선한다
- 비었거나 없는 슬러그는 영문으로 떨어진다 (회귀 없음)
- **완전성은 검사하지 않는다** — 부분적으로 채워진 표가 정상 상태다

### 유일성은 전역이 아니라 캐릭터 단위다 (2026-07-25, Fienn 지적으로 수정)

첫 구현은 채워진 이름 전체에 유일성을 요구했다. 그건 과했다 — `helm`과
`helm-signature`를 둘 다 "헬름"으로 쓰는 것이 **옳은데** 그걸 실패시켰다. 실측:

| 쌍 | 로스터에 동시 등장 | 이름 |
|---|---|---|
| base + `-signature` (13쌍) | **0건** — 로스터가 둘 중 하나로만 해석 | **같아도 된다** |
| 한 base의 모드 후보 (4 base) | **전부** — 4개 base 모두 후보 둘이 함께 실림 | **달라야 한다** |

카탈로그 96개를 통째로 나열하는 화면은 없다(모든 소비자가 슬러그 조회로만 쓴다), 그래서
로스터에 함께 오르지 않는 두 슬러그는 나란히 보일 수 없다.
